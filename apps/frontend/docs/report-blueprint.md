# 报告蓝图与报告体检

入口：工作台 `#editor`（「报告与 PPT」）→ 报告书 →「报告体检」面板；云端项目新建报告时使用默认报告类型的骨架。整体流程见 `docs/report-optimization.md`。

报告质量的提升采用“证据驱动的结构化生成”：数字只来自已登记的分析结果，图、表、公式由代码渲染，结构由研究问题决定，AI 只在受约束的环节参与写作。本页说明其中的**报告蓝图**与**报告体检**。

## 报告蓝图（`lib/report-blueprint.ts`）

蓝图是一个**章节库**，不是某篇报告的目录。它描述调查报告可以包含的章节，以及每一节的目的、写作步骤、建议篇幅、应有的图表和公式，并注明可从哪个模块取得素材。措辞为本系统编写，不取自任何报告。

**通用框架**（每份调查报告都有）：

| 部分 | 内容 |
| --- | --- |
| 摘要 | 背景 → 调查设计（对象、抽样、样本量、有效率）→ 方法 → 3–5 条带数据的发现 → 建议 → 关键词 |
| 研究项目简介 | 背景、意义、文献综述、研究思路（技术路线图）、创新点 |
| 调查方案设计与实施 | 目的、对象与单位、内容与问卷结构、方法、抽样设计（样本量公式与各阶段入样单位表）、任务安排、质量控制 |
| 调查数据处理及检验 | 预调查、正式数据处理（回收量、有效率、剔除规则）、数据检验（使用量表时含信度与效度） |
| 样本特征与描述性分析 | 样本结构与代表性、核心变量分布 |
| 结论与建议 | 调查结论、对策建议、研究局限与展望 |
| 参考文献与附录 | GB/T 7714—2015 著录；问卷、访谈、实施记录（可选）、数据说明、代码与可复现说明、人工智能工具使用说明 |

**分析模块**（按研究问题增删，均为可选）：网络文本与二手资料分析、需求与意愿分析、群体差异与关联分析、影响因素分析、人群细分与画像、评价与问题诊断、方案设计与评估。每个模块对应一类研究问题，详见 `docs/report-optimization.md`。

**报告类型**（`REPORT_TYPES`）是模块的常见起点组合：

| 类型 | 默认模块 |
| --- | --- |
| 现状—问题—对策（默认） | 群体差异与关联分析、现存问题归纳 |
| 影响因素 | 群体差异与关联分析、回归模型分析 |
| 满意度与服务评价 | 群体差异与关联分析、满意度与绩效评价、现存问题归纳、改进措施 |
| 需求与意愿 | 需求与偏好、参与与支付意愿、群体差异与关联分析、人群细分 |

- 「按研究类型重建骨架」时选择类型；之后可从体检或写作指引中插入其他模块，也可删除不需要的模块。
- 章节序号按位置生成：章「一、」、节「（一）」、附录「附录1」，增删模块后自动顺延。
- 新建的各节正文为空。选中某一节时，正文上方显示「写作指引」卡片：本节目的、写作步骤、建议篇幅与当前字数、应有的图表与公式、可取素材的模块。指引不写入正文，因此不会被导出。
- 「插入」某一节时，按蓝图顺序放到合适位置；所属章不存在时一并插入，并只重排带标准序号的标题（自定义标题不改动），可撤销。
- 作者自拟的标题按关键词识别对应的蓝图节，如“基于 K-means 的人群细分”识别为人群细分，“5G 用户满意度评价”识别为满意度与绩效评价。

## 编辑界面

- 章节目录按层级显示：章加粗，节缩进，参考文献与附录弱化；每行一行显示，圆点表示该节是否已撰写。
- 实时预览按报告版式排印：标题黑体、正文宋体两字缩进两端对齐；未撰写的小节显示「待撰写」标记（不导出），旧稿中残留的写作提示以黄色便签标出，提醒导出前删除。

## 报告体检（`lib/report-benchmark.ts`）

按调查报告的通用规范检查 7 个维度、38 项，给出 0–100 分。面板先列出最需处理的 6 项，可展开全部，或点选某一维度只看该维度的缺口；每个缺口附「插入某节」「去某模块」「整理研究发现」等操作。

| 维度 | 检查内容 |
| --- | --- |
| 结构完整 | 摘要篇幅、关键词、通用框架与至少一个分析模块、正文篇幅（按本报告分析图表数估计）、各节是否已撰写、参考文献数量、问卷附录 |
| 方案严谨 | 调查目的与对象、抽样设计与抽样框表、样本量公式、回收量与有效率、预调查、质量控制 |
| 数据质量 | 清洗与剔除规则、信度与效度（仅在使用量表时）、图表是否来自已登记结果 |
| 分析深度 | 推断检验、建模问题有对应方法（仅在设有建模类模块时）、每种方法写出公式、模型检验与适用条件、结果段落含数据、每个分析小节有图或表 |
| 图表规范 | 图文比例、同一结果不重复用图和表、图表标题、每个图表被正文引用、段落长度 |
| 结论可执行 | 已确认发现、发现的行动意义、建议的执行主体与评估指标、研究局限、相关不写成因果 |
| 合规披露 | AI 工具使用说明、文献著录格式、文献均在正文中引用、模拟数据声明、数据与代码说明 |

- **只查适用项**：不适用的检查项不计分；一个维度暂无适用项时显示“尚不适用”，不计入总分。
- **阈值是通用写作规范**，并随本报告的分析规模变化（`BENCHMARK_RULES`），不含任何单篇报告的图表数、公式数或字数。

**边界**：体检只检查结构与证据的呈现方式，不判断研究结论是否正确；正则规则可能漏判或误判，结果用于提示。

## 容量

为容纳章与节分列的完整报告，草稿上限为 100 个章节、120 个已登记结果、2 MB；浏览器（`EDITOR_LIMITS`、`QUALITY_LIMITS`）与 API（`reports.py`）同步校验。

## 验证

- `tests/report-blueprint.test.mjs`：节点唯一且位于所属章内；通用框架与分析模块的划分；各报告类型生成不同且有效的骨架，默认类型不预设任何模型；骨架通过草稿校验，章节类型、标题层级与识别结果一致；作者自拟标题的识别；插入位置、带章插入与重排序号。
- `tests/report-benchmark.test.mjs`：通用模板低分且缺口可补；骨架结构齐全但各节判为待撰写，量表、模型与公式检查暂不适用；证据完整的报告通过对应检查；另一类型的报告按自己的模块判定；图文比例、重复呈现与篇幅随分析规模变化；规则中不含图表或公式的固定数量；因果措辞与未声明的模拟数据被标出。
- API：`tests/test_report_quality.py` 覆盖 100 章节、120 个结果与 2 MB 上限。
