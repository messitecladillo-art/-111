# 选题 Agent v1

选题顾问的首个入口是「选题对话」。现有研究方向、热点线索、地区资料和项目诊断继续保留。Agent 先执行条件核对、资料目录检索、可行性筛选、来源核对、提案整理五个本地工具，再返回可选择的研究提案。连续讨论最多 12 轮，可在发现方向、比较潜力、细化问题和验证计划之间切换。

## 实际行为

- 本地资料研究无需模型 Key，不调用外网；使用现有版本化案例、方法、地区资料和已训练排序器。聊天中的关键词辅助排列方向，不推断学校具有某种渠道，也不把历史热点写成实时新闻。
- 地区、天数、经费和可联系人群可由明确表述形成条件更新建议。用户点击「更新团队条件」后才改变表单；新条件重新筛选，旧提案不直接覆盖新简报。
- 每轮保留所用条件、候选、来源、版本、工具回执、追问、可行性限制与首周计划。使用提案前再次检查上下文、输入修订、来源版本和权限。
- 用户可以显式选择自己的 research 模型服务、候选方向并确认外发材料，再调用一次模型。历史上下文由服务端从已拥有的记录读取，最多摘要六轮，不接受浏览器伪造的历史。模型组织解释和提案，不改变可行性规则。
- 此版本是有边界的多轮研究 Agent，并未新训练通用语言模型，也不自由循环收费、自动联网或代替用户确认题目。赛事阶段和 Gate 不受影响。

### 主题判断与行动计划

资料库研究先识别本轮关注的学科、具体对象与情境，再在现有可行方向中匹配。城市名称用于限定研究地域，不替代主题相关性；“就业”“文娱”等明确关注优先于泛化的地名重叠。排除领域、扩大范围与换题分别处理，普通的“比较这些方向”沿用原候选。用户明确选择的方向保持可见，出现范围冲突时先追问，不静默替用户换题。

现有目录不覆盖具体主题时，返回需要明确的人群、情境和决策问题，不补齐三个无关方向。匹配词表为人工编写的检索辅助，不代表新增实时热点或语言模型训练；硬性资源、地区、时间与经费检查继续使用原有规则。

四种意图各有用途：推荐帮助发现方向；比较显示研究问题、决策、待确认条件和首步行动的对照矩阵；细化优先询问人群、情境与决策边界；规划直接展示拟执行的五步行动。首周计划从确认入口、核对原始依据，到探索记录、取得同意后预试和去留判断，每步都有可检查的记录。计划中的行动不表示已经联系、访谈或回收。

浏览器和服务端使用同一组首周计划参考向量校验，覆盖全部内置方向、入口顺序、空入口和 Unicode 长度。模型提示按四种意图分别约束输出；合成测试只证明提示、调用和回执边界，不能证明真实模型建议质量。

## 记录与恢复

FastAPI 的 `/api/topic-agent/turns` 创建调用；同一路径 GET 读取账户最近 30 条回执，`/{id}` 读取单条。复用 PostgreSQL Operation、现有账户权限和 CSRF 保护，不新增数据库迁移、消息队列或运行时。

请求冻结条件、消息、目的、父轮、候选顺序、模型连接修订及来源版本，使用幂等键和 SHA-256 指纹绑定。新请求同时绑定项目 UUID，独立讨论显式使用 null；旧请求缺少此字段时仍保留原始指纹。服务端先持久化再派发；重复请求先核对旧回执。模型超时、网络或服务器错误造成的结果未知会保留 `outcome_unknown`，相同请求不得另起新键自动重发。旧版缺省和新版 null 表达同一独立讨论范围，未知调用检查也覆盖这两种表示，防止通过升级重发。

浏览器在账户与项目命名空间下保留待核对的原请求。刷新后只读取原回执；原回执不存在时，由用户明确确认后使用同一请求与同一幂等键重新提交。历史来源版本保留用于对账，不能据此直接采用到当前项目。切换账户统一清除上一账户的待处理缓存。

### 按项目继续讨论

项目内的历史列表只读取属于当前项目、当前账户且仍有访问权的调用。独立讨论入口只读取全局记录；旧版未登记项目的历史保持独立讨论，不猜测归属。旧客户端的账户历史查询保留兼容，并在分页前排除无权访问的项目记录。读取项目历史需要当前读取权限，创建新轮次需要编辑权限；撤权后重复请求、单条回执和完整会话均重新校验访问权。

`GET /api/topic-agent/turns/{id}/conversation` 读取完整的根轮至目标轮，检查最多 12 轮、相同项目与模式、父子关系、轮次和时间顺序。该接口不调用模型。失败或结果未知的末轮、旧资料版本可以查看；存在这些状态或已达到 12 轮时不能作为新的续聊起点。

用户点击「继续这段讨论」后，前端恢复模型对话并明确等待下一次提问。历史提案保持供对照的状态，不直接采用、不修改团队条件，也不自动发送新请求。用户重新读取并选择模型服务、候选和发送许可后，新问题才绑定原对话父轮；服务端从已拥有的祖先读取上下文。当前条件变化后重新检查候选，历史解释不替代现有资源条件。

旧版待核对请求可能曾保存在项目浏览器命名空间、但服务器未记录项目。此类请求仅按冻结的独立讨论范围核对费用状态，不能显示为当前项目的提案或用于项目续聊。

访客本地对话仅在当前页面内存中存在；登录用户在当前标签页的编辑缓存中可保留未保存讨论。历史调用回执可单独查询，不会假装恢复已经丢失的本地光标或全部访客对话。

### 地区热点与公开来源

个人模型研究方式下提供公开来源检索，复用知识检索的账户额度、幂等和未知结果恢复。地区、当前关注方向及参考日期形成可编辑短查询；用户点击确认检索后才外发该查询。返回回执展示原查询、来源、片段、检索时间与用量；需要另外勾选这份回执，再确认本轮模型调用，才将其加入模型材料。资料库研究继续只使用内置资料。

勾选绑定不可变回执 ID，而非搜索输入框当前文字。新检索回执会取消旧勾选和模型授权；修改地区、方向、目的、账户、项目或权限后，过期回执不能直接附带。缓存可保留预览，重开不自动检索、不自动附带。待核对模型调用保留原 lookupId 与幂等键；核对不重新检索。

服务端只接受当前账户已完成且用量已核实的检索回执。未就绪、结果未知、内容损坏或其他账户的回执在模型派发前拒绝。旧轮次的来源不会自动重新附带；未纳入本轮材料的旧引用在上下文中标记不可用，不能以历史聊天替代当前来源。

采用提案时只保存该条提案引用的来源，全部 ID 必须在其精确回执中存在。搜索片段在研究简报中保持 `search_excerpt`，保留链接、原查询、检索回执、检索时间和完整 `snippet`；保存与重新载入不升级成已读原文。项目来源允许 2048 UTF-16 单位的 URL、4000 单位的片段；旧版本不含 snippet 的来源继续读取。

## 验证

- `tests/topic-agent.test.mjs`：真实本地工具、连续上下文、条件更新、候选可行性、严格回执与冻结请求验证。
- `tests/topic-agent-quality.test.mjs`：主题、排除、扩大范围、换题、未覆盖主题、行动计划与输入不变性；另有独立封存查询集记录改造前后表现。
- `tests/topic-agent-ui.test.mjs`：真实组件处理器、输入法事件、晚到结果、采用绑定、账户与项目隔离、刷新及原键恢复。
- `tests/knowledge-project-references.test.mjs`：离开选题页后切换账户的缓存清理。
- API `test_topic_agent.py` 与 `test_topic_agent_postgres.py`：请求校验、父轮所有权、12 轮上限、真实 PostgreSQL/RLS、并发幂等、未知调用及重启对账。
- `tests/topic-agent-evidence.test.mjs` 与 API `test_topic_project_evidence.py`：精确引用、搜索片段跨格式记录、中文与 Unicode、旧来源兼容和长度边界。

模型验收采用测试适配器，不消耗用户 Key；它证明调用及回执链路，不代表真实供应商的内容质量或实时热点覆盖。正式使用时仍需使用个人模型服务完成真实联通验收。
