# 本地打包运行器验证

2026-09-30；只使用合成请求、临时本地服务，没有操作阿里云或真实项目数据。

## 已修复

超出字节上限时，请求解析器发出取消信号后立即拒绝并返回 413，不再等待底层取消完成。独立测试包含取消永不完成、拒绝、抛错、中文多字节和分块边界。它不新增无期限读取，不预先缓冲未授权请求，也不改变权限/来源判断顺序。

## 仍未通过的检查

`npm run test:built-runtime` 使用打包后的 Worker、实际静态资源、真实回环 HTTP 和无持久化的临时数据库；每组最多 100 次，首次失败停止该组，不重放失败请求。检查 403、401、415、413、400、正常只读查询、健康恢复、响应头和释放端口。任何异常均使进程退出 1；报告绑定构建模块摘要与配置哈希。

它只覆盖列出的本地路径，不覆盖 Wrangler 的额外代理、云端网络、全部数据库操作、身份入口或 Office 引擎。首次运行前必须重新构建；单次抽样通过也不构成完整发布批准。

## 已排查

- 旧工具链：Wrangler 4.118.0、Miniflare 5.20260730.0-alpha。
- 隔离候选：Wrangler 4.129.1、Miniflare 5.20260907.0-alpha、workerd 1.20260907.1；只安装在本次审计目录，未改应用依赖或正在使用的预览。
- 两组均能在**不加载本应用和 vinext 的最小 Worker**中复现：带静态资源转发的真实 HTTP、POST 有请求体、处理器未读完即拒绝时，连续请求出现连接中断；同轮无静态资源与直接 dispatch 对照正常。这能排除“必须由业务接口代码导致”，不能证明所有失败有同一根因，也不能外推线上云服务表现。
- 最终 Request 上的非等待 cancel、API 优先的资源路由均未修复打包版的失败，未保留这些试验改动。
- 上游 [issue 15203](https://github.com/cloudflare/workers-sdk/issues/15203) 有类似本地症状，但不是本应用根因已被官方确认。上游 [修复提交](https://github.com/cloudflare/workers-sdk/commit/682cd44fcd18940e143b2c63bb7ebf17f3254531) 改善代理错误的进程存活；不代表原始 POST 已正确返回。

证据保存在工作区 `.collab/runs/20260930-production-stream/`。诊断矩阵只是观察记录；正式命令才有逐项断言和失败退出码。不得把旧矩阵的脚本退出 0 写成测试通过。
