# 问卷项目与版本

入口：问卷设计 `/workspace#design` →「问卷项目与版本」。本模块保存待实施设计，不收集答卷，不创建赛事控制项目，不推进 Gate。

## 使用流程

1. 点「连接问卷库」只读取当前编辑身份的目录，不上传或替换当前问卷。
2. 编辑问卷，填写本次版本说明。检查隐私与材料权利后，勾选确认，再点「创建问卷项目并保存」。首次保存建立独立问卷项目。
3. 继续修改并明确保存为下一版本。每版是不可变快照，保存回执不覆盖保存期间的新编辑。
4. 选择项目、预览版本，核对完整内容和结构提示。只有再次确认并点「载入此版本到编辑区」才替换本页设计；可一次撤销。
5. 载入历史版不回滚数据库。重新保存会追加新版本；其他页面抢先保存时拒绝旧基线，要求重新核对，不自动覆盖。

新建、教学示例或恢复本地备份会解除旧项目绑定，防止把另一份问卷误存到原项目。之后撤销内容也不会暗中恢复旧绑定。想保留原项目以外的分支，可「另存为新问卷项目」。

预览之后发生编辑、撤销、重做或文件读取，即使文字又改回原样，也必须重新预览。未完成数值输入、文件读取或站内确认期间禁止保存与载入。

## 保存与身份边界

- 仅显式保存时上传完整已应用设计：研究简介、题干、选项、变量、显示条件、来源及预试备注。不上传原始答卷、模拟答案、未应用的数值或模块拼装输入。
- 不自动保存，不写浏览器持久化存储。未保存编辑与待拼装输入刷新后丢失；本地 JSON 下载备份仍保留。
- 每个身份最多 40 个问卷项目，每项目最多 40 个版本；仍遵守 80 题、每题 30 选项及 300,000 UTF-8 字节的设计容量。上限是工程约束，不是比赛规则。
- 已保存版本没有自动清理或删除入口。请勿输入个人信息、受访者身份、机密或未授权材料；问卷文字本身也可能敏感。
- 沿用报告编辑身份。恢复密钥的归属映射在架构上适用于同一 owner 的已保存问卷；本轮扩展 HTTP 恢复场景尚未完成独立验收。页内未保存内容不能由身份恢复找回。详情见 [身份恢复](editor-recovery.md)。
- 收到身份切换事件立即冻结本页问卷库；过期回执不接纳，不会把旧请求自动归入新身份。已发出的事务不能保证撤回。
- 保存结果不明确时保留原快照和请求令牌，提供「核对并重试上次保存」。重试不是保存当前新编辑，不重复创建原版本。核对前不能载入另一个版本。

服务端 SHA-256 用于内容一致性核对，不证明问卷有效、材料真实、预试完成或获得官方认可。语义不完整的草稿允许保存，但继续标示结构问题和人工复核项。

## 从保存版本到检查与修订

预览版本后，可先读取它已有的机器检查；读取不会创建检查记录。明确同意后，「运行并保存本版检查」会由服务器读取该不可变版本，执行确定性结构检查，再保存源版本、源指纹、引擎版本、问题清单和结果指纹。同一身份、同一版本和同一引擎的重复请求返回原记录，不重复创建；不接收客户端提供的“已通过”结论。检查记录使用独立迁移 `0012_questionnaire_design_reviews.sql`，当前用户数据库未在本轮升级。

检查条目可点击「准备修订此项」，仅选定目标，不替换本页内容。选择后必须重新勾选载入确认，再点「载入此版本并定位问题」，才会一次载入对应版本并定位题目字段或研究简介；仍可一次撤销。空问卷不会因此自动添加题目。切换版本、编辑、撤销、身份恢复等会使待确认操作失效。修订后保存新版本并再次检查，旧检查不会冒充新版本的检查。

前端在接纳预览或保存回执前重新计算完整问卷的规范化 UTF-8 SHA-256，并核对版本号、父版本、标题、字节数、合法 UTC 日期及请求快照。检查结果另行复算并校验结果指纹：即使两份问卷碰巧产生相同问题清单，也不能共享不匹配的源指纹。哈希核验期间发生编辑或身份变化仍须重新预览。

这条链路是“保存版本 → 显式执行 → 持久化机器回执 → 确认载入修订”，不是大模型自主调研、独立人工审阅或赛事 Gate 通过。每版仍需真实的抽样、测量、预试、伦理及适用规则证据。

## 实现与维护

新增 `questionnaire_versions` 追加式表，项目按 `project_id` 分组，最新版本由最大 revision 确定；单次条件 INSERT 完成 owner、容量及基线检查，没有可遗留的空父项目。SQL 触发器拒绝历史 UPDATE/DELETE。重复令牌仅在请求内容完全一致时返回原回执。

迁移为 `drizzle/0011_questionnaire_library.sql`，包含不能从 schema 自动推断的不可变触发器，后续迁移需保留。发布前备份并审核目标数据库迁移；本轮只迁移隔离合成测试库，没有修改用户现有库或阿里云服务。

接口位于 `/api/drafts/questionnaires` 及其项目/版本子路由，复用编辑身份、同源、scope 和有界 JSON 校验。目录不包含问卷全文，查看具体版本才读取快照。保存失败保留页面设计。

## 验收与反思

证据目录：项目根 `.collab/runs/20261002-questionnaire-library/`。

- 作者单元测试 14 项；独立实际 TSX 受控交互测试 25 项通过，覆盖过期预览、编辑中回执、原快照重试、身份冻结及绑定重置。
- 独立真实 localhost HTTP + Miniflare D1 核心 18 组通过，覆盖归属隔离、并发 CAS、幂等、容量和关闭后重建服务的持久性。不是整机重启、全站路由或云端部署验收。
- 扩展检查出现 Windows 原生退出以及超限请求的错误响应中断；完整扩展套件未通过，不把这些失败重试计为成功。缺数据库绑定、新 Cookie 恢复、相同令牌同时竞争等新增场景仍需补验。
- 浏览器预览曾因测试代理透传压缩响应头而连接失败；代理改为按实际解压后字节发送，保留失败记录，不为通过测试而改变产品校验。

这一步补上了问卷产物的持久版本，但诊断提案、动作执行和独立复核尚未形成统一的项目级持久日志。下一步应连接版本化产物与执行/审阅回执，不把版本库称为完整自治 Agent。

2026-10-02 后续复核记录位于 `.collab/runs/20261002-agent-review-closure/`。发现并修复了“问题投影相同但源内容不同仍接纳检查回执”和非法日期被解析器自动归一化的问题；新增定向修订入口。`test:questionnaire` 纳入版本完整性测试及真实路由/仓库配合内存 SQLite 的检查回执测试。后者不是实际 D1、真实 HTTP 或云端部署验收。最终通过数与未完成项以该轮不可变验收记录为准；浏览器连接中断时不得把受控组件测试当作视觉验收。

继续复核记录位于 `.collab/runs/20261002-runtime-review-closure/`。检查接口改为在同一有界读取完成后检查原始 JSON 键：无效内容类型或预告超限的请求不再启动、读取或锁住额外管线。独立反例保留修复前后的结果，常规回归也覆盖头部拒绝后正常检查仍可执行。此修复关闭了可复现的读取边界问题；本地运行器的压缩错误响应、连接复用及历史原生退出须分别看本轮真实 HTTP 记录，不能据此宣称已经全部修好。

上述轮次结束时，修订目标仍只存在页内。后续实现见下节；各轮验收与失败记录保留，不追改历史结论。

## 可追溯修订与复检对比

本轮证据目录：项目根 `.collab/runs/20261002-repair-origin/`。实现和测试状态以该轮验收记录为准；本节描述新增接口与使用边界，不代表整体 Agent 或部署已经验收。

1. 在已保存版的检查记录中选择「准备修订此项」。准备只选择来源，不写数据库，也不替换本页。
2. 核对并确认载入，编辑区保留这次检查的 ID、源版本、源指纹、引擎以及问题位置/代码。普通修改保留修订依据；撤销和重做恢复相应的内容与依据，不自动恢复旧项目绑定。
3. 明确保存为下一版本时，一并提交这项修订依据。服务器从当前身份、同一问卷项目的真实保存记录推导源信息，核对完整源问卷、检查结果和问题成员关系；客户端不能自行填写“已修好”。内容与引用在同一次条件 INSERT 中保存，仍受当前版本基线、容量和不可变约束控制。
4. 新版必须另行显式检查。读取新版或保存修订不会复制旧版检查，更不会隐式执行检查。
5. 新版有检查记录后，按需读取原版和原检查，核验两份完整问卷与两份回执，再对同一引擎的 `(questionId, code)` 比较：仍检出、新检出、不再检出。引擎不同或引用不匹配时拒绝自动比较。

“不再检出”只是该引擎不再报告这一机械问题，不等于已解决、问卷有效或通过人工审阅。删掉题目也可能让问题消失，因此对比另外标明删题。写入预试计划可以消除空字段提示，但不能把尚未实施的预试变成真实证据。

新建、导入本地备份、教学示例及无关载入清除当前修订依据。另存新项目不携带原项目引用。未知保存结果保留原内容、引用和令牌；重试不能夹带后续编辑，也不能在同一令牌下更换修订依据。下载的问卷 JSON 仍只含设计，不包含服务器检查或修订关系；导回时按独立本地设计处理。

新增 `drizzle/0013_questionnaire_repair_origin.sql`：为版本增加可空的引用字段及插入约束，旧版仍为空，保留旧请求指纹和禁止历史 UPDATE/DELETE 的触发器。本轮没有升级现有用户库。部署须先备份并依序审核迁移；未迁移的库不能被本节当作已支持新增接口。

修订依据表达用户选择了某次检查作为修改起点，不是因果证明，也不是人工作出的批准。该记录不新增答卷采集、诊断输入持久化、赛事 Gate 推进或外部模型调用。
