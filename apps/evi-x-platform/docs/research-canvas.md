# 研究画布

入口：工作台 `#canvas`（侧栏「研究与证据 → 研究画布」），或任一工作台页面右上角的「工作台 / 画布」切换。

画布把问卷、数据、统计、图表与成果放在一张图上。它不是第二套工具：统计节点调用「数据分析」同一组函数，引用节点打开工作台里同一个编辑器实例。连线决定数据怎么流动，运行结果与「数据分析」逐位一致（`tests/canvas.test.mjs` 对频数、数值描述、分组、交叉表、Pearson、Spearman、α 与筛选分支逐一比对）。

## 立场与边界

- **画布只保存结构，不保存答卷。** 节点、连线与设置存在本机浏览器（`localStorage`，`research-canvas/v1`）。数据集节点只记录文件名与 SHA-256；刷新后需重新选择同一文件。导出的画布 JSON 同样不含任何行数据。
- **不代写结论。** 「结论草稿」只列出上游结果中的事实数字，结论由人撰写；「报告章节」目前只为频数与信度生成证据段落，其余方法明确列为“需手写”。
- **模拟数据始终标注。** 来自示例数据或硅基样本的数据集在节点、事实清单与证据段落中都标为模拟，不进入真实样本。
- **画布运行不推进项目阶段，也不判定 Gate。** 正式状态仍以 `agentctl.py` 控制面为准。
- **「让 AI 提出方案」暂不可用。** 入口保留并说明原因：本地工作台不调用模型，需在「我的项目」接入模型服务后再开放。

## 节点

| 分类 | 节点 | 能力 |
| --- | --- | --- |
| 研究设计 | 研究问题、材料引用、方法卡、注释 | 注释：不参与运行 |
| 研究设计 / 成果 | 词云与选题、获奖案例、规则与门禁、路演与答辩 | 引用：在原编辑器中打开 |
| 问卷 / 样本 | 问卷、硅基样本预测试 | 引用：摘要来自当前草稿，在原编辑器中修改 |
| 数据 | 数据集、样本筛选、缺失处理 | 运行 |
| 统计 | 频数、数值描述、分组描述、交叉表、Pearson、Spearman、信度（Cronbach α） | 运行 |
| 图表 | 图表（含三线表） | 运行；格式修改不重算统计 |
| 流程 | 结果汇集、人工复核 | 运行；复核绑定上游结果指纹 |
| 成果 | 结论草稿、报告章节 | 运行 |

端口有类型（数据 / 统计结果 / 图表 / 汇集）。不匹配、重复接入单输入端口或形成循环的连线会被拒绝，并在指针旁说明原因。实线是数据连线；顶部与底部的方形端口拉出虚线“说明连线”，只表达研究关系，不传数据、不安排执行。

参考流程（描述与分组比较、量表信度检查、问卷预测试，以及「数据分析」的三条研究路线）插入后每个节点都可修改、删除或重连，不规定论文结构。

## 运行

- **检查**：运行前定位缺失输入、未选变量、类型错误与循环；结果在底部抽屉的「检查结果」中，可逐条定位。
- **运行全部 / 运行所选**：选中节点时，运行按钮给出两个选项，并显示实际会执行的节点数（含必要的上游）。
- **失败只阻塞下游。** 未通过检查的节点被跳过并标为失败，其下游标为已阻塞；互不相关的分支照常运行。运行中出错同理。
- **缓存**：按“节点设置 + 上游结果指纹”缓存。改标题、研究问题或复核备注不会使数字失效；改变量、缺失代码或上游数据会重算。
- **人工复核**：上游结果就绪后需要人确认；确认记录的是当时输入的指纹，上游一旦变化就重新等待确认。
- **取消**：在下一个节点开始前停止，已完成的节点保留结果。

## 与工作台的关系

- 「数据分析」中载入的数据（含示例数据与硅基样本）直接作为数据集节点的默认来源；问卷节点显示当前草稿的题数与结构问题数（打开过「问卷设计」后同步）。
- 引用节点的「打开编辑器」进入工作台中已挂载的同一编辑器；右下角出现「返回画布」，返回后画布定位到原节点。
- 空画布会列出现有成果，可勾选建立为节点引用；不会自动猜测节点间的执行关系。

## 操作与快捷键

| 操作 | 方式 |
| --- | --- |
| 添加节点 | 左上「+」打开节点库：点击添加到视图中央（避开已有节点），或拖到指定位置 |
| 选择 / 多选 | 点击；Ctrl / ⌘ 点击追加；Shift 拖出框选；Ctrl / ⌘ A 全选 |
| 删除 | Delete / Backspace；删除后提示可撤销，原成果文件不受影响 |
| 撤销 / 恢复 | Ctrl / ⌘ Z；Ctrl / ⌘ Shift Z 或 Ctrl Y。一次拖动、一次粘贴、一次自动排布各算一步；连续输入合并为一步 |
| 复制 / 粘贴 / 复制一份 | Ctrl / ⌘ C、V、D。副本使用新 ID，人工复核的确认不随副本复制 |
| 编组 / 解组 | Ctrl / ⌘ G、Ctrl / ⌘ Shift G。编组只整理布局，不决定执行顺序；收起后显示组内状态汇总 |
| 对齐 | 拖动时吸附到相邻节点的边缘与中线；按住 Alt 暂时关闭 |
| 自动排布 | 「⋯」菜单；按数据连线从左到右排列，可撤销；拖动会立即接管 |
| 关闭面板 / 取消选择 | Esc |

输入框获得焦点或正在使用输入法组字时，画布快捷键不响应。

## 动效

所有时长集中在 `Canvas.module.css` 顶部的变量里（毫秒）：悬停 120、按下 90 / 抬起 160、选中 180、出现 220、形变 240、编组 260、排布 300、定位 260、数据传递脉冲 300、退出 160、完成 180、连线绘出 180。

- 节点出现时上浮淡入；删除时原位留下一个淡出的影子，撤销会打断它并以高亮环恢复。
- 新连线沿路径绘出；真实结果传到下一节点时，连线上走过一次脉冲（每次传递一次，不循环）。
- 运行按钮原位变形为进度与取消；自动排布按缓动插值移动，连线随节点移动。
- 「⋯ → 动效」可选标准 / 减少 / 关闭。系统开启“减少动态效果”时，标准自动降为减少（只保留短淡入淡出，不位移不缩放）。

## 性能

画布文档是唯一数据源；React Flow 节点按文档对象身份记忆，拖动一个节点不会重绘其余节点，配置面板也会跳过只改变位置的帧。节点尺寸固定并作为已测量尺寸传入，状态更新时连线不会因重新测量而闪断。上限 200 个节点、500 条连线。生产构建下，200 节点画布约 0.8 秒载入；在无 GPU 的无头 Chromium 中拖动节点（配置面板打开），帧时长中位 16.7 ms、最长 33 ms。React Flow 与画布引擎单独分包，只在首次打开画布时加载。
