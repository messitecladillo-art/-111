# 报告蓝图与对标体检

入口：工作台 `#editor`（「报告与 PPT」）→ 报告书 →「对标体检」面板；云端项目新建报告时直接使用蓝图骨架。

报告与答辩稿的质量提升采用“证据驱动的结构化生成”：数字只来自已登记的分析结果，图、表、公式由代码渲染，结构由蓝图固定，AI 只在受约束的环节参与写作。本页说明其中的第一层：**报告蓝图**与**对标体检**。

## 报告蓝图（`lib/report-blueprint.ts`）

蓝图描述一份完整的正大杯调研报告应包含的章节，以及每一节的目的、写作步骤、建议篇幅、应有的图表和公式，并注明可从哪个模块取得素材。蓝图只取结构，措辞为本系统编写。

| 部分 | 内容 |
| --- | --- |
| 摘要 | 背景 → 调查设计（对象、抽样、样本量、有效率）→ 方法 → 3–5 条带数据的发现 → 建议 → 关键词 |
| 一、研究项目简介 | 背景、意义、文献综述、研究思路（技术路线图）、创新点 |
| 二、网络文本与二手资料分析（可选） | 数据来源与处理、文本分析结果、对问卷设计的启示 |
| 调查方案设计与实施 | 目的、对象与单位、内容与问卷结构图、方法、**抽样设计（样本量公式与各阶段入样单位表）**、任务安排、质量控制 |
| 调查数据处理及检验 | 预调查、正式数据处理（回收量、有效率、剔除规则）、信度与效度检验 |
| 样本特征与描述性分析 | 样本结构与代表性、核心变量分布 |
| 影响因素分析 | 差异检验与相关分析、回归模型（公式、估计表、效应解读、诊断）、人群细分（可选） |
| 评价与问题诊断 | 满意度与绩效评价（如 IPA）、现存问题归纳 |
| 改进方案与评估 | 方案优先级与成本（可选）、分层面措施（问题→措施→执行主体→资源→评估指标）、可行性（可选） |
| 结论与建议 | 调查结论、对策建议、研究局限与展望 |
| 参考文献与附录 | GB/T 7714—2015 著录；问卷、访谈、实施记录（可选）、数据说明、代码与可复现说明、人工智能工具使用说明 |

- 章节序号按位置生成：章「一、」、节「（一）」、附录「附录1」。含可选章节时后续章号顺延。
- 新建的各节正文为空。选中某一节时，正文上方显示「写作指引」卡片：本节目的、写作步骤、建议篇幅与当前字数、应有的图表与公式、可取素材的模块。指引不写入正文，因此不会被导出。
- 「插入」某一节时，按蓝图顺序放到合适位置；所属章不存在时一并插入，并只重排带标准序号的标题（自定义标题不改动），可撤销。
- 新增章节、复制章节、由研究发现生成的章节、统计证据章节都插在当前位置或参考文献之前，不会落在附录之后。

## 编辑界面

- 章节目录按层级显示：章加粗，节缩进，参考文献与附录弱化；每行一行显示，圆点表示该节是否已撰写。
- 实时预览按报告版式排印：标题黑体、正文宋体两字缩进两端对齐；未撰写的小节显示「待撰写」标记（不导出），旧稿中残留的写作提示以黄色便签标出，提醒导出前删除。

## 对标体检（`lib/report-benchmark.ts`）

按固定规则检查 7 个维度、约 38 项，给出 0–100 分。面板先列出最需处理的 6 项，可展开全部，或点选某一维度只看该维度的缺口；每个缺口附「插入某节」「去某模块」「整理研究发现」等操作。

| 维度 | 检查内容 |
| --- | --- |
| 结构完整 | 摘要篇幅、关键词、主体章节、正文篇幅、各节是否已撰写（旧稿中残留的写作提示也计入）、参考文献数量、问卷附录 |
| 方案严谨 | 调查目的与对象、抽样设计与抽样框表、样本量公式、回收量与有效率、预调查、质量控制 |
| 数据质量 | 清洗与剔除规则、信度、效度、图表是否来自已登记结果 |
| 分析深度 | 推断检验、模型、公式数量、模型检验与适用条件、含数据段落占比、方法种类 |
| 图表规范 | 图数、表数、图表标题、正文引用图表、段落长度 |
| 结论可执行 | 已确认发现、发现的行动意义、建议的执行主体与评估指标、研究局限、相关不写成因果 |
| 合规披露 | AI 工具使用说明、文献著录格式、正文引用标注、模拟数据声明、数据与代码说明 |

**边界**：体检只检查结构与证据的呈现方式，不判断研究结论是否正确；正则规则可能漏判或误判，结果用于提示而非评分。满分线约为一份评审认可的优秀参赛报告相应统计的六成（该报告正文论述约 3.3 万字、39 幅图、23 张表、23 个独立公式、57% 的段落含具体数据）。

## 容量

为容纳章与节分列的完整报告，草稿上限调整为 100 个章节、120 个已登记结果、2 MB；浏览器（`EDITOR_LIMITS`、`QUALITY_LIMITS`）与 API（`reports.py`）同步校验。

## 验证

- `tests/report-blueprint.test.mjs`：节点唯一且位于所属章内；骨架通过草稿校验，章节类型、标题层级与识别结果一致；作者自拟标题的识别；插入位置、带章插入与重排序号。
- `tests/report-benchmark.test.mjs`：通用模板低分且缺口可补；蓝图骨架结构齐全但各节均判为待撰写；证据完整的报告通过对应检查；因果措辞与未声明的模拟数据被标出；图表引用只计算引用句。
- API：`tests/test_report_quality.py` 覆盖 100 章节、120 个结果与 2 MB 上限。
