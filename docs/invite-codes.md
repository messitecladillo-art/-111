# 邀请码注册

证见用邮箱验证码登录，不设密码。可以登录的邮箱有两类：

1. **运营方邀请名单**：`EVIX_INVITED_EMAILS` 里的邮箱，同时也是**管理员**，可以发放邀请码。
2. **凭邀请码注册的账号**：持有效邀请码、第一次验证邮箱时注册的账号。之后直接用邮箱登录，不再需要邀请码；它们不能再发放邀请码，邀请不会层层扩散。

## 流程

1. 管理员在“服务与设置 → 邀请码”（`/invites`）填写用途说明、可用次数（1–50）和有效天数（1–30），生成邀请码。邀请码只显示这一次；服务器只保存它的带密钥哈希（`invite/v1`）。
2. 对方在登录页填写邮箱和邀请码，获取验证码。邀请码不区分大小写，空格、连字符与全角字符都可以。
3. 首次验证通过时注册账号，并以一条原子更新占用邀请码的一次使用；用完、过期或已作废的邀请码不再接纳新账号。账号记录它所用的邀请码（`users.invite_id`）。

## 不泄露什么

- 获取验证码的回执对任何邮箱、任何邀请码都相同：外人无法借此判断邮箱是否注册、邀请码是否有效。名单外、又没有有效邀请码的邮箱不会收到邮件。
- 已注册但被移出名单的账号，不能用新的邀请码重新进入，也不会占用邀请码。
- 作废邀请码只阻止之后的注册；已用它注册的账号不受影响。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/code` | `{email, inviteCode?}`，回执同前 |
| GET | `/api/invites` | 管理员查看自己发放的邀请码（不含邀请码本身） |
| POST | `/api/invites` | `{label, maxUses, days}`，返回一次性的 `code` |
| POST | `/api/invites/{id}/revoke` | 作废自己发放的邀请码 |

限制：每位管理员每小时至多发放 30 个，同时有效的至多 100 个。数据表 `invite_codes`（迁移 `0010_invite_codes`）与 `users`、`email_challenges` 一样在未登录的注册路径上读写，不设行级策略，由服务按发放人过滤。
