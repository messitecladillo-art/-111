# 知识搜索：真实浏览器性能验收

本基准使用实际的 `search.ts`、`knowledge.worker.ts` 和 `worker-client.ts`，由本地 esbuild 构建到隔离的 `.collab/runs/20261014-knowledge/browser-benchmark/`。它不进入产品静态资源，不读取用户答卷、OCR 文件、API Key 或项目内容，也不调用后台或互联网。

运行：

```powershell
node scripts/knowledge-browser-fixture.mjs --prepare-only
node scripts/knowledge-browser-fixture.mjs --serve-existing
```

打开 `http://127.0.0.1:3191/`，点击“运行浏览器 Worker 压力测试”。页面会展示完整 JSON 回执，可另行下载。静态服务器只监听 `127.0.0.1`，只服务明确登记的七个基准文件，没有目录访问或写入接口。结束后关闭对应进程。

## 测量范围

- 5,000 条独立 ID 的合成记录，真实索引工厂的 `index.size` 必须为 5,000。
- 使用产品真实客户端与 Worker 消息协议；计时包装只观察工厂返回及消息处理，不修改公式、分词、排序或查询逻辑。
- 构建后预热 20 次，再执行 100 次查询，覆盖中文规范名、缩写、前缀、定义、英文错拼和零命中。
- CPU 查询耗时为 Worker 收到消息后至其提交结果前的时间；不包含结果序列化。
- 端到端耗时为调用实际客户端至收到已解析回执的时间，包含消息传递、结构化克隆和调度；不包含产品的输入防抖、页面渲染或用户操作间隔。
- 索引 CPU 构建与 Worker 启动回执分别记录。查询 P95 使用有序样本第 `ceil(0.95*n)` 项。
- 记录浏览器 UA、逻辑核心数、浏览器可报告的内存、视口、依赖版本、准备时间、Git 基线和三份实际源码哈希。
- 主线程堆与 Worker 堆分开显示。浏览器未提供 Worker 内存时写 `null`，不将主线程内存称为总内存。
- 任何降级到主线程、缺失计时或索引数错误都显示失败，不形成成功回执。

合成记录的审核字段用于测试实际公开索引过滤路径，并不代表 5,000 个真实概念已经完成语义审核。该测试只量测固定数据与查询分布；真实词库增长、不同硬件和长定义仍需另行复测。

## 当前证据

2026-10-15 在 Windows 10 / Chrome 155 实际浏览器中执行，报告 32 个逻辑核心、16 GiB deviceMemory、1280×720 视口。真实索引 5,000，预热 20 次后 100 次查询全部核对正确；Worker CPU P95 23.595ms，端到端 P95 23.965ms，索引 CPU 构建 1034.475ms。客户端为 Worker，无主线程降级。

主线程 JS 堆约 18.1MB→32.3MB；浏览器未提供 Worker 堆，记录为 null，不能合并称为总内存。回执包含源码 SHA-256、依赖版本和全部查询结果，保存在本地 outputs/knowledge-mirror/browser-worker-5000.json。此结果是本机固定合成负载，不是所有设备的性能保证。
