# SAV 与平台编码解释（PR-C）

PR-C 接通「回收文件 → 原码与字典 → 人工确认编码及应答范围 → 现有统计」。它接续 [问卷星文本导出](questionnaire-platform-export.md) 和 [本地 XLSX](local-xlsx-import.md)，保留 CSV/TSV、旧 v1 对应与分析方案。

## 使用流程

1. 在数据分析的「数据文件与读取选项」中选择 SAV。选择文件只在本机核对格式与大小；登录后点击「临时上传并读取 SAV」才发送文件，不需要模型 API Key。
2. 客户端核对文件 SHA-256，服务端临时解析。回执中的文件指纹、字节数、变量字典和清理记录全部通过核验后，用户才能载入。若取消替换当前数据，已核验的回执仍可通过「载入已读取数据」载入，不再次上传。
3. 带入实际需要对应的问卷，在「平台编码与多选解释」勾选本次分析的题目。逐题选择数据列、重编码、缺失策略；多选逐个选项选择真实拆列。XLSX、CSV/TSV 也可进入此面板。
4. 选择共同应答范围，点击「确认本版编码与范围」。结果列出应答记录、多选分母及排除项。配置确认绑定原始数据、列字典、问卷内容和取值规则；应答范围另形成指纹，在送入工作台时重新核验。
5. 点击「送入现有分析工作台」，系统重新计算并比对预览，再建立派生分析表。原表留在同一标签页内，使用「返回原表」可重新解释；不会修改原文件。
6. 在现有分析方案中选择方法并运行，或查看数值描述、分布和信度。题型和计分语义继续参与检查，未把多选二进制列当作独立量表题。

SAV 原码载入后，分析结果、数值汇总和导出先等待编码确认。日期/时间列保留原始编码与显示格式，送入通用分析前需要取消选择它们。取消关联、修改对应或源问卷变化会使派生解释待核对，不退回未经确认的手动数值统计。

## 编码与分母

平台选项序号和问卷的原始编码、分值分别保存。以下是已使用的五题合成验收例，不能推广为所有供应商的固定编码规则：

| 题目 | 文件原值 | 本次确认的解释 |
| --- | --- | --- |
| 单选 SCREEN | `1`、`2` | 明确重编码为 `001`、`none`，保留字符串前导零 |
| 多选 REASONS | 两列各 `1` | 分别对应 `near`、`cost`，选中值 `1`，未选值 `0` |
| 文本 COMMENTS | T01 测试说明 | 保留文本，不用作数值题或量表 |
| 数值 VISITS | `0` | 有效到店次数，保留为 0 |
| 量表 RATING | `1`…`5` | 显式映射为 `-2`、`-1`、`0`、`1`、`2`，原反向计分配置保留 |

重编码输入每行采用 `原值=目标编码`。未列出的值可明确选择「保留原码并核验题目范围」或「暂停，逐项确认重编码」。系统不根据标签、均值或看起来合理的数值猜测分值。标签重复时使用唯一变量名称区分；按标签反查单选时，题目选项标签必须唯一。

多选要求所有选项都有真实数据列，缺列不补 0。选中与未选编码必须非空、不相交，未登记编码暂停解释。

| 行的状态 | 应答者分母 | 选择次数分母 |
| --- | --- | --- |
| 所有拆列为明确未选值，如全 `0` | 计入一个已答应答者 | 增加 0 次；总次数为 0 时比例显示「—」 |
| 所有拆列空白 | 记为未答，不计入 | 不计入 |
| 部分拆列空白 | 默认暂停；用户可明确选择已有作答时将其按未选解释 | 确认该策略后按实际选中次数计入 |
| 命中额外缺失码或已选择排除的 SAV 用户缺失定义 | 整道多选题该行记为缺失排除 | 不计入，单独记录排除数 |
| 分支外 | 不进入共同应答范围 | 不计入 |

「占应答者」为该选项选中人数／该题已答应答者数；「占选择次数」为该选项选中次数／该题全部选中次数。各选项的应答者比例可以合计超过 100%。合成例中一个应答者选了两个选项，两项各为 **100%／50%**。

条件父题先按明确重编码解释。默认范围策略核验跳题，无法判断或分支外作答时暂停；用户可选择仅采用确定符合全部所选题条件的行。这个共同范围与原表、每题是否作答及统计的完全案例范围分别记录，不把已读取行数当成有效问卷数。未知或异常行不自动插补。

## 数据字典、版本与恢复

- SAV 返回原始编码；值标签、系统缺失 `null`、逐变量用户缺失值与范围、原格式、测量层级和日期编码分别保存。分析表把系统缺失显示为空白，原回执保留 `null`。
- 用户缺失默认保留原码，只有选择「采用文件中登记的缺失值与范围」或填写额外缺失代码才排除。有效 0 不默认视为缺失。
- 原始列标签在解释与派生表中继续保留；姓名、学号等原标签仍参与标识字段检查。
- v2 数据身份包括原文件 SHA-256、实际行内容、列字典和解析器信息。确认还绑定问卷及映射配置；派生身份登记源解释指纹、映射指纹、范围指纹及源行／选中行数。
- 分析记录和写作摘要分别列出原表与当前共同应答范围的行、列数。JSON 登记原表解析身份、派生身份与映射／范围指纹，范围内的缺失和重复检查不标成原文件口径；下载不包含答卷行。
- 「下载 v2 配置」保存问卷和对应规则，不含原始答卷。备份的 `confirmed` 总是清空；恢复后也不会复原批准，必须针对重新读取的相同数据和问卷再次确认。界面拒绝把逐列编码规则不同的备份悄悄改为统一规则。
- 已有 CSV/v1 方案按原语义继续工作；不会自动升级为 v2 或自动更改缺失、分支及选项解释。不同解释指纹的方案需要重新核对。
- 数据、原表与解析回执当前保留在标签页内。刷新后重新读取文件、恢复 v2 配置并确认，再恢复匹配身份的分析方案。临时上传不创建云端原始数据版本。
- **SAV 原表与 v2 派生数据暂不发送给研究画布。** 原有 CSV/TSV/XLSX 非 v2 流程继续使用已有共享机制；以后接入画布需要完整继承字典、范围和语义检查。

本批只复用已有频数、数值描述、分组描述、交叉表、Pearson、Spearman 与信度。分组描述没有升级为显著性检验；没有 EFA、回归或 p 值占位结果。不推进赛事阶段，不标记 CLI Gate 通过。

## 私有转换接口

`POST /api/imports/sav` 接受原始文件字节，使用同源会话与现有 Origin/CSRF 校验：

| 请求或回执 | 内容 |
| --- | --- |
| `Content-Type` | `application/octet-stream`，不接受压缩内容编码 |
| `X-CSRF-Token` | 当前登录会话的令牌 |
| `X-EVIX-Temporary-Upload` | 必须明确为 `accepted` |
| 成功 JSON | `survey-import/sav-v1`，包含原码行、变量字典、源 SHA-256 与清理回执 |
| 清理回执 | `cleanup.completed:true`、`reason:"temporary-upload"` |
| 失败 JSON | 沿用 `{error:{code,message}}`；解析器内部路径或答卷内容不返回 |

鉴权和限额事务在读取文件前结束，解析期间不占用数据库连接。返回结果前再次检查会话；撤权或退出后不交付结果。客户端只发出一次请求，不自动重试；面板总等待上限为 60 秒，超时、断网或错误后由用户手动重新读取。上传进度只显示可观测的读取状态，不生成百分比或假完成状态。

API 仅在 PostgreSQL 保存既有 `RateEvent` 限额事件，操作日志只包含不透明导入 ID、状态与时间，不登记文件名、题干、标签或答卷。本批不新增数据库迁移、消息队列或模型调用。

## 运行与部署

API 使用现有 Python **3.12**、PostgreSQL、非 owner 应用角色和 Alembic 迁移流程；[pyreadstat 1.3.6](https://pypi.org/project/pyreadstat/1.3.6/) 固定在 `pyproject.toml` 与 `uv.lock`。测试的 pandas 属于开发依赖。沿用 [API 运行说明](../apps/backend/README.md)，在 API 目录安装锁定依赖：

```powershell
uv sync --locked --no-dev
# 跑测试时显式包含开发依赖；使用配置好的合成 PostgreSQL 测试库。
uv sync --locked --group dev
```

SAV 新增环境变量如下；身份、发信、生产 HTTPS 和数据库配置沿用 API 现有要求。

| 环境变量 | 默认值 | 允许范围或要求 |
| --- | --- | --- |
| `EVIX_SAV_TEMP_DIR` | `.local/sav-imports` | 私有本机目录，不包含 `..`，不位于公开文件服务目录 |
| `EVIX_SAV_UPLOAD_SECONDS` | `20` | 1–60 秒 |
| `EVIX_SAV_PARSE_SECONDS` | `15` | 1–60 秒 |
| `EVIX_SAV_CLEANUP_SECONDS` | `60` | 30–3600 秒，启动与周期清理 |
| `EVIX_SAV_HOURLY_IMPORTS` | `12` | 每用户每小时 1–60 次 |
| `EVIX_SAV_GLOBAL_HOURLY_IMPORTS` | `120` | 全局每小时限额，不小于用户限额，最大 1000 |

本地 QA 通过 `EVIX_API_ORIGIN` 把 Next.js `/api/` 请求转到 FastAPI；已验证同一会话的 3184 → 8182 二进制上传。生产部署按既有同源反向代理配置，不开放匿名转换入口。

每个 API 进程允许最多 **2 个转换、每用户 1 个**，完整鉴权／上传操作最多 8 个。该并发限制是进程内的；每小时次数限制由 PostgreSQL 事务串行登记，跨进程和重启保留。不能把多进程的瞬时并发解释为全局 2 个。

三个数据库回调在线程执行，每次回调以约 2.5 秒的绝对截止约束全部查询，并设置事务局部 `statement_timeout`，锁等待最多 1 秒；路由的回调业务截止为 3 秒。取消或截止后仍等待线程关闭事务再释放资源，Python 线程不能强制终止；连接池等待和清理可能超过业务截止。关闭服务等待整个已登记操作，上传阶段也不能在关闭后启动解析。

### 容量与执行边界

| 项目 | 上限 |
| --- | --- |
| 输入文件 | 2,000,000 字节 |
| 数据 | 5,000 行、80 列、200,000 单元格，任一超限拒绝而不截断 |
| 单个文本值或元数据字段 | 2,000 个 UTF-16 单元 |
| 数值 | 有限且绝对值不超过 JavaScript 安全整数界限；拒绝不可表示值 |
| 子进程结果及前端 SAV 契约 | 12 MiB |
| HTTP 响应体边界 | 16 MiB |
| v2 配置文件 | 500 KB |

解析在一次性 Python 子进程内运行，标准 SAV 原码由固定版本 pyreadstat 读取。Windows 临时目录 DACL 只授予服务身份和 SYSTEM，拒绝符号链接、junction 及越界路径；Linux 代码设置私有目录权限和内存／CPU／文件大小 RLIMIT。它们提供权限与资源边界，**不构成完整的 OS 安全沙箱**；生产 Linux、限制权限的服务身份和容器资源配置需要部署验收，本轮未以 Windows 测试替代。

## 临时文件与异常恢复

每次处理使用独立 `sav-<不透明ID>` 目录。子进程必须完成 PID 登记并得到父进程确认才能读取文件。成功、失败、超时和取消均先终止／回收已知子进程再清理；清理回执缺失或删除失败不能返回成功。

启动与周期维护检查已过期租约。只有能确认进程状态及路径边界的任务才清理；旧租约、未知启动间隙或尚未登记的子进程保留为 `deferred`，不猜测删除。Windows 短暂共享冲突有有限重试，清理等待可以晚于解析截止。

运维发现 `cleanup_failed` 或长期 `deferred` 时，按日志的导入 ID 核查对应目录、租约、父／子进程及服务权限和磁盘空间，再处理已确认无活动进程的任务。保留原租约用于核对；不要清空整个临时根目录，也不要在进程状态未知时强删。服务正常重启后继续走相同核验流程，不重放上传请求。
