# 研究简报到问卷：页面接入验收

本批基于 `26103c73e28b2d0dbec205c7087f2043850a8bbc`（PR #29），将已确认的项目研究简报接入现有问卷编辑器。没有更换编辑器实例，也不自动创建调查题目、选项或实际调查结果。赛事 CLI 阶段与 Gate 不受影响。

## 使用路径

1. 在项目内保存研究简报，并确认精确版本。
2. 点击“带入问卷设计”，选择原题对应的研究问题与概念。
3. 预览字段变化，逐项勾选采用内容。
4. 点击“确认应用并保存新版本”。内容与来源绑定由后台同一事务保存。
5. 在原编辑器继续修改、撤销、重做或载入历史；保存恢复结果会新增版本。

未勾选字段、稳定题目 ID、题干、选项及显示条件保持原值。用户仍决定研究结构和采用范围。

## 保存与恢复

- 草稿缓存、撤销和历史记录同时携带正文、来源绑定与恢复来源。
- 来源修改、确认撤回、账户/项目变化、未完成输入或版本冲突会阻止旧提案提交。
- 保存结果不明时保留原始内容与幂等标识；核对不创建新的请求。
- 核对期间的新编辑保留在本页，用户明确选择保留草稿或载入云端版本。
- 保存状态、编辑权限、输入状态分别展示。临时等待不会伪装为只读权限或提案过期。

## 2026-10-15 实测

Windows、Node 24.15，标准 Next.js 生产构建连接本地 FastAPI/PostgreSQL 合成验收环境；邮箱、项目和问卷均为专用测试内容，未调用真实模型或检索供应商。

实际浏览器操作并以数据库独立核对：

| 场景 | 观察结果 |
|---|---|
| 已有手工问卷，选择标题与研究问题/概念关联 | 问卷 v2 正确保存；原题、两项选项及未选地域保持原值 |
| 后台事务提交 201 后，测试中间件中断回执 | 页面保留待核对请求；原请求重试恢复同一个 v2，没有额外版本 |
| 撤销应用并保存 | v3 恢复原内容与空来源绑定 |
| 载入历史 v2 并保存 | v4 恢复对应内容与精确来源绑定 |
| 退出、邮箱验证码重新登录、重新打开项目 | 恢复云端 v4，初始空白编辑器不产生错误的未保存提示 |
| 未保存题干后连续切换选题/问卷 20 次 | 文字、selectionStart/selectionEnd 保持一致 |
| 第二次提交后中断回执，等待时继续编辑题干 | 核对恢复 v5，晚到回执没有覆盖新编辑 |
| 明确保留手工草稿并保存 | v6 保留等待期间的题干及原绑定 |
| 连续撤销两步后保存 | v7 恢复较早内容，仍能正常保存 |
| 1280×720、1440×900、1920×1080 | 无页面横向溢出，每种尺寸仅一个问卷编辑器；测试后恢复原视口 |

浏览器发现的“回执待核对时误报只读/未完成输入/提案过期”已修复，并在同一故障流程中复验：三个误报均未出现，核对按钮可用，真实内容变化仍使旧提案失效。

测试证据保存在本机忽略的 `.collab/runs/20261015-topic-questionnaire/evidence/`：`p6-browser-db-v1-v4.json`、`p6-browser-db-v1-v7.json`、两轮实际事务故障记录以及类型、lint、回归和构建日志。七个版本的操作依次为 `edit/apply/restore/restore/apply/restore/edit`，未覆盖历史版本。

独立代码复核关闭了连续撤销恢复来源、编辑器发布前提前确认和临时等待状态混淆的问题。最终待核对状态改动另有 41 项宿主/面板测试及五个独立异步反例检查。

本次提交对应的前端回归为 1,341 项：1,324 通过、17 项既有跳过、0 失败；范围沿用正式单元运行器，并排除另批尚未提交的县域发布合同测试。全应用类型检查、lint 和标准 Next.js 生产构建通过，构建后运行环境检查通过 198 项。API 事务验收属于前置 PR #29，未因页面接入重写。

## 仍需后续环境验收

真实 Windows 中文输入法候选交互、生产邮件送达、真实模型供应商、部署恢复和真实团队调查仍按对应批次验收。浏览器填入中文与组合事件测试不代替原生输入法实测。县域内容、发布工具及推荐模型扩充不包含在本页面接入提交中。
