# 项目报告的只读权限

项目的 `writable` 权限沿 HostedReport → EditingStudio 的 `projectBinding.readOnly` 传递。viewer/reviewer 进入现有报告时可以阅读、切换预览、查看版本和下载 JSON、Word、PPTX；正文、发现与矢量编排、格式、分镜应用、LaTeX 源码修改、备份恢复、撤销与重做及保存入口均遵守只读权限。

权限变更不会重新创建编辑器或清空当前正文、选择、历史、PPT、发现数据或 LaTeX 内容。已有未保存内容继续保留，仍可下载备份。原有分镜关联检查、研究蓝图、格式设置、发现插入、正文与附录导出及 PPTX 导出继续使用当前实现，没有引入旧 A1 画布。

每次已提交的只读权限变化都会推进写入 epoch。回调与异步操作使用创建时的 epoch，权限降级后失效；后来恢复编辑权限也不会重新授权旧回调。集中编辑入口、撤销/重做、命令式章节/发现追加、排队发现提案、备份读取与历史恢复都检查该能力。HostedReport 对快照回传、统计章节提案及云端保存同样设防，不能只依赖按钮的 disabled 状态。

云端最新或历史版本的载入也绑定发起时的权限 epoch，在发起和每次异步读取完成后复核。权限变化后，旧回执不能替换本地草稿或重新创建编辑器。当前只读用户仍可主动载入云端版本，因为读取只检查 epoch 是否仍有效，不要求写权限。

已经发往服务器的保存请求可能仍然完成。权限变化后，旧回执不会更新本地报告头或清除原幂等请求；恢复权限后可使用当前入口核对同一次保存。服务端的项目角色鉴权仍是服务器写入的最终边界。

新增 `tests/report-readonly.test.mjs` 执行实际组件及事件回调，使用受控 hooks、文件 Promise、计时器、网络与下载替身，覆盖权限降级/恢复、延迟备份、排队发现、旧保存回执及只读下载。它不是浏览器 DOM 或真实云端鉴权测试；原有 editor/storyboard 回归还检查实际导出文件及报告关联。发布验收仍需检查实际浏览器的角色切换、焦点与下载。
