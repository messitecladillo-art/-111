## 本批行为

新建且尚无问卷的托管项目先进入选题。已有项目保留问卷入口；离开再返回时恢复上次工作标签，并挂载该标签的实际编辑区。问卷和选题编辑器在标签切换时保持挂载。

同一项目的条件、候选比较、自拟题目、研究问题、构念、来源和验证记录合为一份研究文档。原有本地选题入口和缓存保持兼容。已采用候选固定显示在三题比较中，避免选中方向与比较目录脱节。

所有者和编辑者可以保存；复核者和查看者只读。PostgreSQL 保存不可变版本，确认和撤回绑定精确版本及内容哈希。新版本不继承历史确认。保存使用期望修订和幂等标识；回执不确定时保留原请求，并核对当前云端状态。并发冲突不会覆盖本地草稿。

`0006_topic_projects` 增加项目版本和决定记录，包含租户 RLS、引用完整性和不可变约束。应用/schema revision 同步升级。使用现有 Alembic 升级流程，部署前备份数据库并先在独立环境验证迁移。

这次没有接入简报到问卷的字段提案；该部分为下一独立批次。地区目录和县域资料也按单独批次推进。页面不会把未接通的入口显示为可用功能。网页确认不推进赛事 CLI 阶段或 Gate。

隔离环境：Next.js 生产构建、本地 FastAPI、专用合成 PostgreSQL，邮件和模型使用测试适配器，没有调用真实收费模型。

2. 修改题目后显示未保存且确认失效；保存、确认 v2，写入明确标为合成验收的反例记录并保存 v3。

4. 独立新页面从服务器重开 v3，记录正确恢复；历史 v1 载入为草稿，不继承确认，保存后形成 v4，旧版保留。
5. 另一窗口基于旧 v3 保存被拒绝，显示版本冲突并保留原编辑；明确载入最新版本后恢复。
6. 1280×720、1440×900、1920×1080 实际页面宽度与文档宽度检查无横向溢出；检查浅/深色、正文编辑及右栏操作。键盘 Tab 从研究问题进入对应移除按钮。
7. 最终构建中进入数据分析、返回项目列表并重开项目，恢复分析标签且实际内容可见，不再出现仅有选中标签的空白区。

尺寸核验读取的是实际目标标签的 `innerWidth/innerHeight`，不是仅凭尺寸设置调用成功。临时尺寸覆盖已恢复。

Next.js 的 `/api` 代理目的地在构建时由 `EVIX_API_ORIGIN` 固定。独立测试后端使用 8182 时，构建与启动都设置 `EVIX_API_ORIGIN=http://127.0.0.1:8182`；只在启动时设置不会改变已有构建中的代理目标。
