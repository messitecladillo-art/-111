# Agent 候选稿与质量审阅工作台

本次重建基于仓库 `3bc2ca680af0c835a2c9f68ce186f5de2c626438`。原下载包已失效，本版本重新实现并重新验证，不沿用旧包的提交编号或验收结果。

本功能用于 `agent_ui`。它把报告生成、来源校验、有限返修、用户审阅和原稿采纳串成可核对的流程。生成成功代表收到了一份候选稿，最终事实、统计方法、文献原文与导出文件仍需独立验收。

## 使用路径

1. 按 [P0 本地运行](p0-running.md) 安装和启动 Next、FastAPI 及 PostgreSQL，并执行所有现有 Alembic 迁移。本次没有新增依赖或迁移。
2. 登录后在“模型设置”中保存模型服务，开启报告能力并选定服务。DeepSeek 的凭据应填写在该页面，由后端凭据库保存；对话框拦截直接粘贴的密钥。
3. 在 `/agent` 选择项目，准备调查设计、数据与已登记分析结果。研究计划可以没有采集数据；教学演示必须明确选择；实证模式需要项目、用户数据和来源一致的登记结果。
4. 点击“生成候选稿”，核对课题、资料范围、服务、模型版本、输入版本和最大调用次数，确认后发起本轮运行。
5. 观察真实章节进度和调用回执。可取消生成；已派发调用仍可能结算，需要核对回执。刷新或重进页面只提供结果核对，不宣称后台任务会自动续跑。
6. 在审阅区检查“质量检查 / 原稿对比 / 实际修订”。锁定旧章节会保留该节全部原内容；锁定候选新增章节会排除该新增内容。
7. 点击“采纳所选变更”。系统先备份旧报告，再保存新稿。资料或原稿变化、存在待消费的编辑、质量被阻断或浏览器存储失败时，采纳不会覆盖当前内容。
8. “最近原稿版本”保留最近三次报告快照。恢复只替换报告，不回滚问卷或数据，恢复前仍备份当前稿。

本地报告快照按账号与项目隔离；访客采用会话存储。问卷与数据在当前 Agent 页面访问期间按项目保留，切换项目再返回可以恢复；它们不因此变成已经同步到后端的持久数据集。浏览器关闭或刷新后，未保存到相应托管模块的数据仍需重新载入。

## 质量与交互约束

| 环节 | 本次行为 | 验收边界 |
| --- | --- | --- |
| 输入 | 固定问卷、数据、报告和输入 SHA-256；实证结果校验来源与结果指纹 | 指纹一致只能说明登记内容一致，不能证明真实田野已经完成 |
| 起草 | 主体章节后再综合结论与摘要；事实锚点只来自登记证据 | 仍需核对论证适用范围与未登记的事实 |
| 返修 | 仅收到正文且内容不合格时有限重写，保存实际 before/after | 不构造虚拟“六位导师已审阅”记录 |
| 调用 | 服务版本绑定、先预约再调用、幂等、速率与并发限制 | 断网后不把未知结果当作无费用失败 |
| 异常 | 鉴权、限流、额度、服务或输入变化以及未知结果停止后续分发 | 已在途的请求可能仍结算；需要读取已有回执 |
| 用量 | 汇总服务商返回的输入、输出 Token，缺失时标为未完整报告 | 不估算输入/输出比例，也不把缺失回执计为完整的零用量 |
| 审阅 | 候选稿只读预览、章节差异、真实修订、锁定与采纳 | 质量状态为 draft / needs_review / blocked，deliverable 始终为 false |
| 导出 | 保留已有 Word、LaTeX 和打印/PDF 入口，候选预览禁用插入编辑 | 此轮未对具体最终报告做 Word/PDF 分页、图表和匿名验收 |
| 视觉 | 保留证见青绿品牌、深浅主题，响应式审阅卡和运行记录 | 动效仅表现实际事件；支持减少动态及键盘操作 |

独立审稿、统计前提、文献原文、文件导出、渲染及提交门禁，在没有相应证据时保持 `not_run`。完整度分数不能替代交付验收。

## 接口与状态

前端只提交已保存服务的 ID 和版本，不接收客户端传入的 API Key 或供应商地址。Next 固定向运营方配置的 API Origin 发送请求，并转发同源会话和 CSRF 上下文。后端每次调用及外部 I/O 返回后都校验当前权限、服务版本和报告能力。

| 接口 | 用途 |
| --- | --- |
| `POST /api/agent/full-report` | 验证完整输入、校验 SHA、通过 NDJSON 返回章节进度和最终候选稿 |
| `POST /api/agent/report-sections/preflight` | 保存有时限、绑定账号/项目/输入/服务版本的运行授权 |
| `POST /api/agent/report-sections` | 预约并执行一个章节调用，返回可核对回执 |
| `GET /api/agent/report-sections/{id}` | 查看单次章节回执 |
| `GET /api/agent/report-runs/{runId}` | 查看本轮元数据和章节调用状态，不重启生成 |

章节回执状态为 `running / ready / failed / outcome_unknown`。UI 中的 `dispatched` 只表示当前请求已发出，不伪称后端已经成功预约。

一轮最多处理 26 个章节；每节起草与返修分别最多两次尝试。理论上限为 104 次调用，实际数量取决于正文质量及停止条件。服务端按账号限制每小时 120 次、同时最多 6 次；运行授权有效两小时。未知结果的阻断指纹不会因更换 run ID、幂等键、prompt 或 attempt 自动解除。

## 验证方式与未完成项

下载包中的 `_delivery/verification.json` 与 `_delivery/logs/` 记录这次重建的实际测试结果。前端使用仓库正式单元测试文件清单，以并发 4 执行；六组旧 D1/Office HTTP 套件继续依照仓库规则排除。共享契约、TypeScript、ESLint、仓库布局、生产构建和后端定向回归另行记录。

浏览器验收运行真实 Next 页面和真实 Chromium，以明确合成的账号、模型服务和 NDJSON 回执隔离外部依赖；它验证界面交互，不等同于真实 DeepSeek 或 PostgreSQL 端到端验收。

本环境没有 `EVIX_TEST_DATABASE_URL`，相关 PostgreSQL 验收按既有机制跳过，不以 SQLite 代替。正式使用前应在专用测试数据库上运行新增 PostgreSQL 套件，确认预约、RLS、并发和撤权行为，再完成真实模型服务联调。密钥和本地认证材料不包含在下载包中。

下一阶段如需后台断点续跑，应引入持久任务队列、任务事件存储和明确的恢复授权。当前版本通过回执核对控制未知状态，没有把页面刷新包装成自动恢复执行。
