# 提交前体检

本批在既有研究工具旁新增 `/preflight`，无需登录即可进行 Word / PowerPoint 本地初检；工作台的「质量保障」也提供入口。完整 DOCX / PPTX / PDF 检查需要邮箱登录，并由用户逐份确认临时上传。两种检查均不使用模型或 API Key，不改写原文件，不推进赛事阶段或 Gate。

## 使用路径

1. 选择或拖入文件，按需要填入学校、成员、指导教师和团队名称。工具品牌词由用户选择加入。
2. 点击「本地检查」，查看作者属性、批注修订、PPT 隐藏页及备注、XML 身份词、嵌入对象、外链和缩略图的位置。
3. PDF 的对象、附件和历史内容，以及 Office 图像元数据，可通过「完整文件检查」读取。确认框说明当前文件和临时用途；取消不会发起上传。
4. 在原软件中处理问题后重新导出、重新检查。下载的 JSON 记录绑定文件字节数、SHA-256、身份词配置哈希、实际覆盖和问题位置。

修改身份词后，旧结果保留供查看，下载须等待当前配置重新检查。移除文件、取消检查、离开页面或切换账号会取消相关操作，晚到结果不会写回。文件列表和检查结果只在当前页面内存中保存；刷新需重新选择文件。

首次进入先完成现有账号上下文的初始化，再启用文件选择，避免已登录账号的初次回执重置刚选中的文件。匿名账号或账号查询失败后仍可进行本地检查。

## 覆盖与结果语义

| 范围 | 自动检查 | 保留的人工项目 |
| --- | --- | --- |
| 浏览器本地 Office 初检 | ZIP 实际展开预算、主文档类型、作者/自定义属性、批注/修订、隐藏页/非空备注、缩略图、嵌入对象、活动内容/外链、指定身份词（含分段文字和属性） | 图片元数据需完整检查；图片中文字、页面外观和适用规则人工核对 |
| 浏览器本地 PDF | 指纹及范围记录，不将未扫描的 PDF 显示为通过 | PDF 对象检查待完整检查 |
| 服务端完整检查 | 复用仓库 `audit_submission_files.py`，读取 Office 图像元数据以及 PDF 元数据、对象、附件、动作和可读取的历史结构；另校验实际解压与物理边界 | OCR/渲染画面、身份词清单是否齐全、届次/组别/赛区/阶段适用规则 |

结果只有「发现待处理项」「已检查范围未发现问题」「有待完成的检查」三种含义。无法读取、发现项目超过 500 条或检查依赖未就绪，不能给出完整检查成功。记录不是匿名保证、赛事门禁通过或最终提交许可。第十七届未明确的适用格式要求不在本功能中硬编码。

图像元数据沿用现有审计器的可读范围：单个值最多读取 8,192 字符，嵌套深度最多 8；不将此范围解释为所有图像格式和全部载荷都已解码。页面画面、像素和完整匿名判断仍由人工核对。

## 资源与取消边界

- 每份文件 20 MiB，每批最多 5 份、合计 50 MiB；文件名最多 240 个 UTF-16 单元。
- 身份词最多 128 个，每词最多 64 个 UTF-16 单元，规范化 JSON 的 UTF-8 长度最多 4 KiB。中文、大小写和 Unicode 规范化在前后端使用同一合约。
- Office 最多 2,000 个 ZIP 条目、实际展开总量 64 MiB、单部件 8 MiB。不执行宏、外链、公式、脚本或文档动作。不向磁盘解出 Office 压缩包。
- 本地 Office 解压使用直接锁定的 `pako@3.0.2`。分块读取时限制实际输出，并检查单个 DEFLATE 流完整结束、全部输入消费、长度及 CRC；不依赖不同浏览器或 Node 版本对多余压缩内容的处理差异。
- 服务端不接受未列出的 ZIP 间隙、伪造的展开长度、重复/碰撞路径、不支持的 ZIP 扩展载荷或错误文档根。遇到这些情况须从原软件重新导出，不能按干净文件处理。
- PDF 预检限制 50,000 个对象；检查回执最多 2 MiB、问题最多 500 项。
- 本地任务在独立 Worker 内执行，最长 30 秒。服务端默认上传 30 秒、子进程解析 35 秒；页面等待上限 75 秒，无自动重试。数据库新连接和连接池等候各限 3 秒。
- 服务端每进程最多 2 个完整检查，同一用户同时 1 个；默认每用户每小时 12 次、全局每小时 120 次。浏览器最多同时 2 个检查。

## 服务端部署与临时文件

新增 `POST /api/submission/preflight`，沿用现有会话、Origin 与 CSRF 校验。原始文件以二进制请求体发送，`X-EVIX-Temporary-Upload: accepted` 表达此次确认；名称、格式和规范化身份词由专用头传递。API 和浏览器共同校验回执与输入文件/配置相符；仅在清理确认后提供成功回执。

Python 依赖使用现有 `uv.lock`，锁定 `pypdf==6.20.1`、`Pillow==12.3.0`、`defusedxml==0.7.1`；XMP 安全解码器是必需依赖，未安装不能返回完整检查成功。源码运行时使用仓库内的既有审计器；wheel 构建通过 `force-include` 收入同一文件，并校验固定 SHA-256，缺失或不同内容会返回依赖错误。构建 wheel 时须从包含 `skill/zhengda-cup-champion/scripts/audit_submission_files.py` 的仓库构建，不能只复制 API 子目录。

| 设置（`EVIX_` 前缀） | 默认值 |
| --- | --- |
| `PREFLIGHT_TEMP_DIR` | `.local/submission-preflight`，私有且不属于项目文件目录 |
| `PREFLIGHT_UPLOAD_SECONDS` | 30 |
| `PREFLIGHT_PARSE_SECONDS` | 35（可配置 1–35） |
| `PREFLIGHT_CLEANUP_SECONDS` | 60 |
| `PREFLIGHT_HOURLY_IMPORTS` | 12 |
| `PREFLIGHT_GLOBAL_HOURLY_IMPORTS` | 120 |

每次上传使用随机任务目录、私有权限、租约和子进程记录。成功、读取失败、超时、取消及有确定所有权的重启遗留均进行清理；日志仅登记随机任务标识、时间和结果状态，不登记文件名、身份词、内容、验证码或密钥。清理失败不返回成功。

重启后仍有存活进程，或恰好在创建子进程时崩溃而无法确定其身份的任务，清理器会保留并登记 `deferred`，交由管理员核对，不冒险删除活动任务。Windows 使用私有 DACL 和独立解释器，不是操作系统沙箱；Linux 子进程另加 CPU、地址空间和文件大小限制。实际子进程与合成数据库测试已在本地 Windows 和 GitHub Actions 的 Ubuntu 环境完成；云端部署及强隔离需另行验收。

## 验收入口

- Web：`npm run lint`、`npx tsc --noEmit --incremental false`、`npm run test:unit`、`npm run build`；专用测试为 `tests/submission-preflight.test.mjs`、`tests/preflight-upload.test.mjs`。
- API：运行现有 pytest，需明确的合成 PostgreSQL 数据库与独立非所有者应用角色；专用测试为 `tests/test_submission_preflight.py`、`tests/test_submission_preflight_api.py`。私有 DACL 的真实 Windows 子进程测试须在可读取该测试私有目录的用户身份下运行。
- 浏览器：匿名本地检查、登录后确认上传、取消/移除、配置变化、账号切换、下载校验、DOCX/PPTX/PDF 问题定位，桌面 1280×720 / 1440×900 / 1920 宽屏；深浅主题、键盘与减少动态样式一并检查。

本批不改已有问卷、分析、画布执行器、SAV 数据转换、官方规则或 Claude 首页。教师多队视图和后续分析补强仍按原计划分批交付。
