# Agent 角色执行与恢复

任务每次推进一个角色。Research 完成后保存回执，下一次推进才交给 Reviewer；研究设计或问卷经过审阅后，仍由用户确认。任务的数据库版本与流程位置是两个字段，返修不会复用旧调用。

## 调用顺序

1. 检查当前登录会话、团队角色、任务版本；锁定团队、项目、任务及已有回执后，再次检查并锁定登录会话。等待锁期间退出登录时，不启动调用。
2. `prepare_step` 准备一个角色的输入副本。没有数据、没有注册处理器或任务已结束时，不创建执行回执、不调用模型。
3. 将任务标为运行中，同时保存 `AgentTaskExecution`，提交事务。回执以任务 ID 与请求版本唯一标识。
4. 在数据库事务外执行处理器。异步处理器直接等待，同步处理器在线程执行；两者都只取得隔离的输入副本，不能通过修改它改变项目状态。
5. `apply_result` 验证实际返回结果：结构、大小、引用、问题和错误信息必须一致；审阅决定还必须与结构化审阅内容一致。校验失败不发布部分产物。
6. 重新验证团队写权限、锁定当前任务及回执后，再次检查并锁定登录会话至提交完成。只有原执行仍在运行、任务版本和输入快照均未改变时才写回结果。

`WorkflowEngine.advance` 和 `LangGraphRunner.advance` 保留原有同步库接口。HTTP 使用 `prepare_step/apply_result` 的单角色边界，不能用旧的整段同步调用绕过执行回执。

## HTTP 契约

已有创建、列表、详情、批准和补充输入接口保持原路径。

| 请求 | 行为 |
| --- | --- |
| `POST /api/projects/{project}/agent-tasks/{task}/advance`，`expectedRevision` | 执行最多一个角色，返回任务及 `execution`；同一请求版本返回原回执，不重复执行 |
| `GET /api/projects/{project}/agent-tasks/{task}` | 任务当前状态及最近执行回执；不调用处理器 |
| `GET /api/projects/{project}/agent-tasks/{task}/executions` | 最近 100 条回执，按请求版本倒序；不包含密钥、提示词、原始答卷或模型结果正文 |
| `POST /api/projects/{project}/agent-tasks/{task}/cancel`，`expectedRevision` | 取消正在运行步骤的结果发布；晚到结果不能覆盖取消状态 |

执行回执提供 ID、角色、输入任务版本、占用任务版本、输入哈希、有效结果哈希、开始/结束时间、租约期限和固定错误码。没有收到可用结果时，`resultHash` 为空。哈希用于核对版本，不证明供应商收费或真实调查发生。

同一版本重复请求时，返回的任务是当前任务状态，`execution` 是那一次请求对应的回执。客户端不能用旧回执的完成状态替代当前任务状态；用返回的最新任务 `revision` 发起下一步。

## 状态与故障

| 执行状态 | 含义 |
| --- | --- |
| `running` | 已登记，正在等待处理器返回 |
| `completed` | 处理器返回且通过结构校验；任务可能仍待补充材料、审阅或人工确认 |
| `failed` | 明确拒绝调用，或收到无法应用的结果 |
| `outcome_unknown` | 超时、执行中断、未确定异常或租约过期；不自动重发 |
| `cancelled` | 用户取消了本次结果发布；已发生的外部调用可能仍运行或计费 |
| `discarded` | 权限或任务版本已改变，返回内容不写入项目 |

自定义处理器默认执行期限为60秒，租约90秒；显式模型桥接使用下文的110/140秒限制。同步函数超时后线程可能继续工作；其返回值不能再次进入提交路径。没有租约续期或自动接管机制。

进程重启后，GET 会将过期运行显示为待核对，且不修改数据库。下一次授权写操作可将对应回执持久化为结果未知。旧版本留下的、没有执行回执的运行任务也会阻塞，不能把它当作未执行重新发起。

终态回执及其身份字段不可改写。取消和超时保留原记录，不能清空后自动重试。逐次模型回执已在下文接入；确认外部结果的人工对账与恢复队列仍待实现。当前接口不提供“强制成功”或“未知结果重发”。

## 权限与迁移

部署先运行 `uv run alembic upgrade head`，再运行应用。`0010_agent_task_executions` 引入执行回执表；部署必须继续应用当前版本的全部后续迁移，不能停在 `0010`。应用要求的版本见 `evix_api/runtime.py` 的 `SCHEMA_REVISION`，部署步骤见[后端运行说明](../apps/backend/README.md)。启动会拒绝旧数据库版本；执行回执迁移不重写已有任务和成果。

任务与 HTTP 回执读取仍要求当前项目成员身份，推进和取消要求 owner/editor。成员被移除、降为只读或退出登录后，迟到结果不能进入项目。个人模型 Key 不进入任务状态、回执或日志。

数据库 RLS 允许执行发起者在撤权后完成自己的**最小元数据回执**，用于记录 `discarded`；该表没有输入/结果正文，API 仍不向失去项目权限的人返回回执。这个例外不授予项目内容读写权限。普通成员仅能读取，其他团队不可见。

## 当前能力边界与下一项工作

### 分步骤模型绑定

创建任务可以额外提交 `modelPlan`，将前端选择固定为服务器核验过的个人服务版本。例如：

```json
{
  "taskType": "topic_design",
  "requirements": {"goal": "团队填写的研究方向"},
  "modelPlan": {
    "schemaVersion": 1,
    "default": {"serviceId": "00000000-0000-4000-8000-000000000001", "revision": 1},
    "roles": {
      "reviewer": {"serviceId": "00000000-0000-4000-8000-000000000002", "revision": 3}
    },
    "steps": {
      "research.design_research": {"serviceId": "00000000-0000-4000-8000-000000000003", "revision": 2}
    }
  }
}
```

示例 ID 只是格式说明。真实请求必须引用当前账号已保存的服务。优先级为具体步骤、角色、默认配置；提供计划时必须覆盖该任务涉及的全部角色步骤，包含 Reviewer。未使用的显式配置也核对归属和版本，有失效项时不静默忽略。步骤身份与角色内部工作流有回归对照，不能自行增加名称。

服务器在 `state.model_bindings` 保存版本 1 的规范快照：个人 `ownerId`、具体步骤、`serviceId`、精确 `revision` 和所需 `capability`。不保存 Key、密文、服务地址、模型正文或付费授权。Research/Data 按 `research` 能力检查，Survey 按 `questionnaire`，Writing/Reviewer 按 `report`；这里是产品能力声明匹配，不是供应商能力或连通性证明。

真正派发一个新角色前，在任务和服务行锁持有期间重新检查其绑定。服务被删除、版本已变、能力不符，或推进者不是绑定的个人账号时，拒绝新执行，不创建回执、不改变任务位置。队友仍可阅读、批准和补充输入；无绑定的历史任务保持原协作行为，序列化不增加空字段。同版本旧回执的返回先于模型预检，所以服务后来撤回不妨碍对账。

快照是应用层的权威路由元数据，由应用层完整校验；编排层只携带有大小限制的 JSON，不反向导入应用层。公共 Agent 适配器没有把它放进任务 `context`、角色输入或提示词。

绑定本身不授予费用权限。下文的模型桥接使用精确版本和明确授权，在逐次调用前保存回执，不会在提交后换用最新配置。当前接口不提供修改既有任务绑定的捷径；用户需要新建任务并重新选择，历史记录保留。

默认装配条件和逐步调用限制见下文。未配置模型或工具时仍明确阻塞。已有对话、问卷提案和报告拟稿的个人模型连接保持原有路径与同意机制。

完整研究链仍需：

- 在实际供应商环境中核验协议、用量与明确拒绝/未知结果的对应。合成测试与MockTransport通过不能代替供应商联通或收费对账。
- 接入真实资料读取、统计执行、产物存储与导出，工具只能返回实际产生的引用。
- 使用持久队列和独立执行器支持关闭页面后的持续工作；本批请求内执行不能代替该能力。
- 建立人工对账及明确确认后的恢复流程。回执查询不等于恢复任意内部步骤。

这些应用任务始终与赛事 CLI 阶段、Gate 分开，不会通过模型结果自动推进赛事控制面。

## 验证入口

`test_workflow_step_execution.py` 检查单角色准备与提交、非法结果、状态隔离和审阅返修。`test_agent_execution_postgres.py` 通过真实 PostgreSQL、迁移、普通应用角色及 HTTP 检查并发重复请求、锁释放、超时、取消、撤权、重启和迟到结果。`test_agent_tasks_postgres.py` 保留团队协作与任务身份保护回归。

测试使用合成处理器和独立测试数据库，不能据此声称供应商联通、收费对账或完整研究报告已验收。

`test_agent_full_progression.py` 从 Research 跑到 Reviewer，覆盖研究、问卷确认和数据输入门禁。测试使用合成角色决定，并执行 CSV 统计与 TeX 源码构建。另以 PostgreSQL HTTP 回执验证明确拒绝、调用结果未知和重复请求不重发。

模型绑定专项以合成处理器验收：纯契约46项、真实PostgreSQL迁移/RLS及HTTP绑定7项通过；包含既有执行与编排的定向回归合计135项通过。独立复核另验证跨成员旧回执对账和伪造绑定拒绝。共享TypeScript契约67项通过。上述不包含真实供应商或费用调用。Windows全库串行回归在既有临时上传子进程测试出现等待，个别用例单独运行可通过；完整结果与Linux/PostgreSQL16 CI须在PR逐项登记，不能按专项通过替代全库通过。

## 显式授权的逐步模型调用

没有注入自定义 `workflow_handlers` 时，应用现可为带 `modelPlan` 的任务装配真实模型步骤适配器。它使用现有个人服务配置，支持当前 OpenAI、DeepSeek、Qwen、兼容接口、Anthropic、Gemini 协议；实际模型名仍由用户服务配置决定。注入可信自定义处理器的部署保持原路径，无绑定的历史任务也不自动调用模型。

先读取 `GET .../agent-tasks/{id}/model-preview`。返回本次角色、精确模型配置、最多调用数、输出 token 上限、允许外发的材料和 `previewHash`。预览同时绑定任务版本、实际角色及步骤提示词和输出 Schema 的内容哈希。后续步骤会使用本角色前面步骤的有界结果，这类衍生材料在授权范围中明确列出；预览不声称包含尚未生成的逐字提示词。

用户确认后，调用 `POST .../advance`：

```json
{
  "expectedRevision": 0,
  "modelConsent": {"accepted": true, "previewHash": "预览返回的精确哈希", "maxCalls": 3}
}
```

缺少确认或预览已过期时拒绝派发，任务仍保持可确认状态。研究目标、范围与约束采用字段白名单，任意原始答卷、图片、音频及附加上下文不属于该接口的模型材料契约。人工返修反馈可进入下一次明确授权。文献摘录还需要已登记的证据引用；本批没有新增原件读取/引用登记接口，不能将这一前提描述成已连通的完整文献检索链。

流程为：HTTP 校验 → 提交角色回执 → 独立线程运行公共 Agent → 每步独立数据库 Session 检查权限、父回执/租约、服务版本、提示词哈希和限额 → 提交私有调用回执 → 模型请求 → 回写调用回执 → 角色 Schema 与引用核验 → 原角色提交边界。`system` 与 `user` 在六类协议中分别传输；模型不能执行代码或自行调用工具。

逐次调用复用 `Operation` 表和现有个人 RLS，scope 为 `workflow-model-call/v1`，调用 ID 由父执行 ID 与步骤确定。回执在网络请求前提交，不保存 Key、提示词或模型正文；保留实际输入/结果哈希、个人服务版本、授权哈希、时间、状态和供应商返回的 token 用量。`GET .../model-calls` 仅供调用者查看；同队其他成员保留已有成果读取与审阅权限。调用完成只说明本次模型返回，角色结果还须通过独立的结构、来源和证据约束。

模型角色具有110秒执行上限与140秒租约，每次HTTP调用沿用30秒上限。外层异步取消立即关闭本次调用令牌；线程可能稍后结束，因此每一步及结果提交还会核对持久父回执、会话与团队权限。取消、超时、撤权或登出后不启动后续模型步骤，迟到输出不能进入成果。预约后崩溃、超时、5xx等未知结果保留对账状态，不因重复请求、补料、批准或新请求 nonce 自动重发；没有恢复收费调用的后门。

数据角色在没有实际读取/统计工具时于付费调用前明确阻塞。Writing 仍不能凭模型文本生成导出引用；Reviewer 不能凭模型判断认证提交文件已就绪。此桥接没有新增搜索、原文读取、统计或导出工具，也没有提供持久队列。现有前端整篇报告入口尚未切换到此API；真实供应商联通、前端授权卡和完整研究交付需分别验收。

回归入口为 `test_workflow_models_postgres.py`、`test_workflow_model_transport.py`，并重跑旧模型协议、角色工作流、绑定、执行回执和分层检查。测试模型输出均为明确的合成夹具，HTTP 供应商请求由 MockTransport 拦截，没有真实费用或实证研究产出。
