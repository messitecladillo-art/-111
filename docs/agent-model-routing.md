# Agent 的模型分工与调用边界

证见 Agent `/agent` 的三种已有模型调用分别选择个人服务：对话研究、问卷起草、报告拟稿。它们复用已有的研究、问卷、报告能力权限。`/services` 的“任务分工”用于安排各任务的模型，“服务接入”管理模型配置与密钥；Agent 内也可在右侧模型设置区域打开。同一服务可用于多项任务，每项也可选择不同服务。

输入框底部仅提供当前对话模型和对话方式的快速切换，以及进入完整设置的入口。长期配置不放在该弹窗内。

只有一个可用服务且没有既有选择时，界面使用该服务作为起点；有多个服务时由用户选择。明确选择的服务被删除或移除能力后，任务保持待选择，不自动使用另一个付费服务。选择按账户保存在当前浏览器，只保存服务 ID；不保存 Key 或模型配置。未登录状态不写入共享偏好。

## 当前调用如何配合

| 任务 | 入口与选择 | 实际执行与结果 |
|---|---|---|
| 对话研究 | Composer 的“对话研究”，要求 research 能力 | `/api/agent/turns` 校验个人服务、版本及同意，调用已有 Provider。最多三轮工具反馈；每条链固定最初选择的服务。模型提出的改动继续经过原有确认。 |
| 问卷起草 | 模型设置的“任务分工”，确认表单可再次选择，要求 questionnaire 能力 | 读取项目问卷版本，经问卷提案 API 生成待审提案；用户应用后才改变问卷。未知结果保留原请求，显式核对时沿用幂等标识。 |
| 报告拟稿 | 模型设置的“任务分工”，要求 report 能力 | 沿用章节拟稿 API，只发送用户确认的本节材料和登记事实。数字仍由原有事实引用机制处理，用户确认后才写入报告。 |

服务商及模型来自用户已配置的服务，不按品牌自动分配“最佳模型”。模型 ID 由用户填写，不固化某一代型号。OpenAI、DeepSeek、千问沿用原有 Chat Completions 路径；Anthropic 使用 Messages，Gemini 使用原生 generateContent。其他兼容服务仍需运营端批准目的地址。

适配只覆盖这条研究调用需要的非流式文本输出；没有把厂商的生图、语音、嵌入或原生工具功能一并宣称为已接入。真实连通和模型质量还需分别验收。

## 源码职责

| 位置 | 唯一职责 |
|---|---|
| `apps/frontend/lib/agent/model-routing.ts` | 能力筛选、选择解析、账户偏好存储、确认绑定比较；不发网络请求 |
| `components/agent/generation.tsx` | 读取账户项目与服务；问卷确认、版本读取、提案调用、未知结果核对 |
| `components/agent/Composer.tsx` | 当前对话模型快速切换；不解密 Key、不决定后端授权 |
| `components/agent/ModelRoutingSettings.tsx` | 完整任务分工界面，消费相同账户偏好与能力解析 |
| `components/hosted/HostedServices.tsx` | 服务接入和任务分工的两个设置页签，配置保存仍经后端授权 |
| `components/agent/AgentShell.tsx` | 调用已有对话/拟稿客户端、展示确认、执行允许的工具、保护迟到回执与账户变化 |
| `lib/agent/router.ts` | 用户操作契约；付费确认可绑定账户、登录轮次、服务 ID 及配置版本 |
| `components/agent/threads.ts` | 账户隔离的本地会话；保存请求时的服务 ID、版本、模型名及供应商标识。它不是服务商签名回执。 |
| 后端现有 application 服务 | 权限、配置版本、幂等、调用前回执、真实 Provider 请求、结果未知状态 |

模型确认卡生成后变更服务、版本或账户，会重新要求确认。旧版保存的卡片没有绑定信息，也需要重新确认。后续对话的免重复确认范围包含配置版本，编辑服务后不会继承旧版本同意。

对话、章节拟稿与回执读取会捕获账户和登录轮次。账户变化或原会话删除后，迟到结果不会继续执行工具；等待知识索引或搜索完成后也重新检查。服务在请求发出后被编辑时，后续模型调用仍携带原版本，由服务器决定是否拒绝；不自动改投新服务。

## 与五角色工作流的区别

`multi_agent` 的 Research、Survey、Data、Writing、Reviewer 是另一套有类型的角色工作流。当前应用默认没有注册真实步骤执行器；前端三项选择不会自动让那五个入口开始执行。

接通五角色仍需：异步执行适配、调用前持久化的步骤回执及未知结果处理、数据文件与真实统计工具、成果存储和导出、恢复与审核流程。不能在数据库项目/任务锁内直接调用付费模型，也不能用通用文本生成替代真实统计或导出回执。维护时从这些缺口继续，不重新复制一套 Agent。

## 验证范围

- `agent-model-routing.test.mjs`：三项能力隔离、失效选择、精确同意、账户与跨标签页偏好、存储读取/写入失败。
- `agent-model-consent.test.mjs`：执行真实 AgentShell 处理函数，覆盖旧卡改模型/版本、旧版卡、运行链服务固定、账户切换、删除会话、迟到 GET 回执与知识索引等待。
- 浏览器验收使用构建后的前端及明确拦截的合成 HTTP 响应，检查界面到请求体的服务 ID/版本，不代表真实服务商联通或后端权限验收。

前后端服务能力、真实回执与版本检查保持各自职责。单元测试、浏览器夹具和真实模型联通分别记录，跳过测试不算通过。

## 原生协议维护

`infrastructure/llm.py` 按 provider 构造请求并解析响应，不把 Claude/Gemini 响应伪装成 OpenAI `choices`。API Key 仅置于对应认证请求头；原生目的地址与后台白名单一致。Gemini 模型 ID 限单个合法名称，不能当任意 URL 路径。所有协议保留超时、大小限制、禁止重定向和不自动重试；截断、拒绝、工具调用、阻断及未知响应不能当完成文本。

协议依据：[Anthropic Messages](https://platform.claude.com/docs/en/build-with-claude/working-with-messages)、[Gemini generateContent](https://ai.google.dev/api/generate-content)。本地测试用 MockTransport 核验字段、认证头、解析与失败状态；未产生真实服务商费用。
