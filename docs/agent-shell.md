# 证见 · 镜室：Agent 外壳（第 1 步）

`/agent` 把整个平台组织成一个垂直 Agent：一段对话贯穿始终，每个已有模块是 Agent 走进的一间“房”。经典工作台 `/workspace` 保持原样，两者共用同一套模块与交接仓库（`useWorkbenchModules`）。

## 界面

| 区域 | 内容 |
|---|---|
| 标题栏 | 品牌、当前房间与项目名、全局搜索、昼 / 夜、经典工作台、账号 |
| 房间栏 | 前厅 · 研究动线（选题 → 规则 → 问卷 → 抽样 → 分析 → 画布 → 报告 → 答辩）· 镜廊（案例库、硅基样本，只映照不下结论）· 工具 |
| 对话 | Agent 的回复、工具卡（细线框）、确认卡（双线框，y / n）、知识镜词条卡 |
| 镜面 | 前厅显示照度图、盲区与证据链；其余房间承载原模块，访问过的模块保持挂载 |
| 命令行 | 自然语言与 `/` 命令共用；`/` 弹出命令表，↑ 在空行回看历史；输入法组字时 Enter 不发送 |
| 状态线 | 项目 · 房间 · 照度 · 盲区 · 体检 · 指令模式 · 存储状态 |

宽度：≥1600 px 三栏并排；1025–1599 px 在房间里对话改为浮层抽屉，房间独占镜面；≤1024 px 对话与镜面二选一；≤720 px 房间栏收入抽屉。快捷键：任意处按 `/` 进入命令行，`Ctrl/⌘ + \` 收放对话，`Ctrl/⌘ K` 全局搜索。

## 照度只来自看得见的证据

照度（`lib/agent/illumination.ts`）是每间房检查通过的比例，盲区是未通过的检查及其去处：

- **问卷室**：有题目、无阻断问题、每题映射研究问题与分析计划、写明决策目标与调查对象（`questionnaireIssues`、`questionIsMapped`）。
- **分析室**：已载入数据、已登记分析结果、已确认研究发现。
- **报告室**：报告体检总分（`benchmarkReport`，满分 100，换算为比例）；报告仍是空白模板时照度为 0，模板自带的结构分不算光。

其余房间显示“照度待接入”，不估算、不编造。全亮（█）只表示该房间检查全部通过。

## 指令模式

第 1 步没有接入模型。`lib/agent/router.ts` 是确定性路由：

- 命令：`/下一步` `/照度` `/盲区` `/查 ‹词›` `/夜` `/昼` `/清空` `/经典` `/帮助`，以及每间房一个进门命令（`/问卷` `/报告`…）。
- 常用说法：“下一步做什么”“问卷还缺什么”“打开分析室”“什么是设计效应”“切换到浅色模式”。
- 一句话涉及两间房时请用户先选一间；读不懂的长句直说听不懂；概念问题从知识镜原文照录定义、公式（KaTeX）与出处，不改写。
- 会改动的动作（目前只有清空对话）先出确认卡。对话记录只存在本标签页的 sessionStorage，与项目数据无关。

## 视觉语言

颜色只表达证据状态：金 = 有来处的数字，青 = 生成未核实，青绿 = 方法与命令，红 = 仅用于错误。等宽字体画结构与状态，正文用黑体，标题用宋体。三种动效：**显影**（新回复里的金色数字从噪点收拢）、**光扫**（房间照度上升时扫过一道光）、**镜移**（换房间时新模块从镜中翻出）；减弱动效时全部退化为淡入或静止。

## 第 2 步接入点

- `RouterContext` 与 `AgentTurn` 是 LLM 主循环的输入与输出形状：模型回复将以同样的工具卡 / 确认卡渲染。
- `ProjectView` 是 Agent 可读的项目状态；写入仍经由各模块自己的交接通道。
- 照度检查清单扩展到抽样、答辩等房间时，只需在 `illuminate` 中加入对应房间。
