# 证见 Agent：对话优先的工作台

`/agent` 把整个平台组织成一个垂直 Agent，布局参照 Codex 桌面版：左侧是对话与项目，中间是一段对话，平台原有的每个模块都在右侧面板里打开。经典工作台 `/workspace` 保持原样，两者共用同一套模块与交接仓库（`useWorkbenchModules`）。

## 界面

| 区域 | 内容 |
|---|---|
| 图标栏 | 对话、模块菜单（按研究流程 / 参考 / 工具分组，附照度）、项目全景、知识镜搜索、浅色 / 深色、账号 |
| 侧栏 | 新对话；项目（登录后列出你的托管项目，归入项目的对话收在项目下）；最近（其余对话）；搜索标题与说过的话（按内容找到时显示命中的那一句）；重命名（行内按钮或双击标题，Enter 保存，Esc 放弃；两个标签页都改过时以后改的为准）；删除对话前在原处再确认一次 |
| 对话 | 顶部是对话标题与所属项目。空对话显示“我们要研究什么？”与几条建议；回复里有工具卡（细线框）、确认卡（双线框，y / n）、知识镜词条卡、模型提案卡 |
| 输入框 | 上方两枚标签：归入哪个项目、草稿存在本地还是云端项目。下方：“＋”打开导入数据 / 问卷 / 提交文件的模块；“改动前确认”说明权限；模型服务选择；发送。`/` 弹出命令表，↑ 在空行回看历史，输入法组字时 Enter 不发送 |
| 右侧面板 | 模块本身，访问过的保持挂载；面板头有模块名、照度、“在经典工作台打开”、铺满、关闭。左边缘可拖动调宽，宽度记在本浏览器 |

面板跟随地址里的 `#模块`，模块之间互相跳转（例如分析把结果送进报告）时面板一起切换。

宽度：模块按整屏排版，所以屏宽小于 1680 px 时，打开面板会自动收起侧栏，关闭面板后恢复；用户在任一状态下手动展开或收起，各自记住。面板默认占侧栏以外空间的七成（至多 1240 px），对话至少保留 360 px；“铺满”暂时收起对话，让模块占满。手机布局暂不考虑。

快捷键：任意处（输入框外）按 `/` 进入输入框，铺满时会先把对话带回来；`Ctrl/⌘ B` 收放侧栏；`Ctrl/⌘ \` 关闭或重新打开面板；`Ctrl/⌘ K` 知识镜搜索。

## 对话归谁

对话按身份保存（`components/agent/threads.ts`）：登录用户存在本浏览器的 localStorage（每人一个键），访客只存在本标签页的 sessionStorage。会话状态未确认前不显示任何已存对话，换了账号只读到该账号自己的。登录状态确认前在本页说的话归入随后确认的身份；访客在本标签页里的对话，登录后并入该账号，退出登录后访客看不到账号的对话。两个标签页同时使用同一账号时，保存前先合并另一页的改动，删除的对话不会被旧副本带回。每个身份最多保留 60 段对话，每段 160 条。对话以第一句话为标题，可在输入框上方或起草问卷的确认卡里归入项目；起草时选定的项目会把尚未归档的对话归进去。对话记录与项目数据无关，`/清空` 只删除这段对话。

## 项目记忆（v1）

托管项目可以保存一份**项目档案**：研究意图、已确认决策和开放问题。它跟着项目走，不跟对话走。入口在托管项目页的“项目档案”标签；Agent 的项目全景会显示摘要并链接过去。

- 只有负责人和编辑成员可以写入；复核成员与只读成员只能查看。
- 保存会生成新的不可变版本，记录确认人、时间和修改说明；空项目可以从已确认的选题带入建议，但仍需人工检查并保存。
- 不含原始数据行、问卷全文或报告正文；没有项目、访客或离线时明确显示“没有项目记忆”。
- 模型每轮只拿到服务端生成的约 2k 字摘要，不会收到浏览器自行拼装的记忆正文；记忆与当前问卷/报告冲突时，以模块当前版本为准。

本版只覆盖研究意图、决策与开放问题；证据索引、依据变化（stale）、模型提议和团队并发确认按 [项目记忆规格书](superpowers/specs/2026-10-29-agent-memory-design.md) 的后续切片接入。

## 照度只来自看得见的证据

照度（`lib/agent/illumination.ts`）是每个模块检查通过的比例，盲区是未通过的检查及其去处：

- **问卷设计**：有写了题干的题目（自带的空白题不算）、无阻断问题、每题映射研究问题与分析计划、写明决策目标与调查对象（`questionnaireIssues`、`questionIsMapped`）。
- **抽样设计**：抽样框已写进报告（从抽样设计一键插入后登记为 `sampling-frame` 结果，同一方案按组只计一次）、每个抽样框写明计划有效样本量、有效回收达到计划（数据已筛查，或最新质控结果对应当前数据）。
- **数据分析**：已载入数据、已登记分析结果（抽样框不算分析）、已确认研究发现。
- **报告与 PPT**：报告体检总分（`benchmarkReport`，满分 100，换算为比例）；报告仍是空白模板时照度为 0，模板自带的结构分不算光。

其余模块显示“照度待接入”，不估算、不编造。全亮只表示该模块检查全部通过。

## 回溯：每一个数字的来处

`/来处`（或“图 3-1 的数字从哪来”）沿光路回溯报告里一个图表：图表 → 登记的结果（方法、有效样本）→ 计算范围 → 质量控制剔除 → 数据文件与指纹 → 变量对应的题目。每一步都读自结果登记时平台记下的内容（`lib/agent/provenance.ts`），不重建、不推测；对不上问卷设计里题目的变量会直说。项目全景的证据链下方也有入口。

`/结果`（或“登记了哪些结果”）列出报告里登记的分析结果：方法（按报告里的名称）、有效样本 / 总数、前几项统计量（金色）与提醒，教学模拟数据单独标出，缺失的统计量不显示、不补零；从抽样设计写进报告的抽样框是计划，单独列出计划样本量，不算分析结果；最后是已确认的研究发现。`/结果 ‹标题、方法或变量›` 只看相关的几项，统计量更全。结果存在报告里，所以这次访问打开过报告与 PPT 之后才读得到，此前直说读不到。

## 写进报告

`/写入`（或“把结果写进报告”）把还没写进报告的登记结果按报告蓝图写进对应章节：先出确认卡，列出每项结果去哪一节、其中有几项是教学模拟数据；确认后交给报告与 PPT，按编辑器自己的“写入报告”同样的方式写入——方法说明与公式（同一方法全报告只写一次）、图或表、以“由图 x-y 可知”开头的读数段落，章节不存在时按蓝图新建，整批一步可撤销。数字全部来自登记结果，Agent 不改写。已经写进报告的结果（有它的图表，或只有读数段落的结果有原样的读数段落）不会再写一次；确认卡确认得晚、其间被删掉的结果跳过。`/结果` 的每一项都标出是否已写进报告。模型也可以请求这一步，同样先出确认卡。

## 写报告：逐节计划与按事实起草

`/写报告`（或“写报告”“报告还缺什么”）按报告蓝图逐节列出这个项目的报告写到哪：章节作标题，每一节标出未建（＋）、空（○）、进行中（◐）或到位（●），已写字数与蓝图建议的篇幅、还缺的元素（图、表、公式、引用）；下面是报告体检里最该补的几项。大纲来自项目本身——蓝图的必备章节、报告已有的可选章节、登记结果所属的章节——不套用任何范本的章节或数量（`lib/agent/report-plan.ts`）。最后给出下一步：有登记结果没写进报告就先 `/写入`，否则起草第一个空的章节。

`/起草 ‹章节›`（或“帮我写研究背景”“起草「研究意义」”）用你自己启用了「报告」能力的模型服务起草一节（`POST /api/agent/drafts`，后端 `multi_agent/agents/writing_agent/services/section_draft.py`，与模型对话同样先记账再调用、幂等、限流每小时 20 次、同时只有一份在生成、回执可读不重调）：
1. 每次起草都先出确认卡，写明发送什么：这一节的蓝图要求（目的、写作步骤、需要的元素、建议篇幅）、课题名称与目的、若干条事实、已确认研究发现的标题与解释、本节已有正文；不发送问卷题目、原始数据与其他章节正文。
2. 事实（`lib/agent/draft.ts`）来自登记结果：每项结果的方法与有效样本、统计量、表中前几行的数字，抽样框的计划样本量；属于这一节的结果排在前面，最多 80 条，编号 F1…Fn。
3. 数字规则：模型只能用占位符 `{F3}` 引用事实，自己写了任何阿拉伯数字（含全角）或引用了不存在的事实，那一段整段丢弃并计数——后端丢一次，浏览器再查一次。需要的数字没有时写“（待补：…）”。占位符由浏览器换成事实里的数值，模型的文字原样保留（其中的 `$`、`[[` 不会变成公式或交叉引用）。
4. 拟稿在对话里显示为未经核实：模型的文字为青色，填入的数字为金色；“写进「…」”把它交给报告与 PPT，作为一步可撤销的写入放进蓝图对应的章节（没有就新建），“重新起草”再问一次。结果不明的显示“核对回执”，只读回执、不再调用模型。起草调用同样记进对话记录，计入调用模型的次数。

## 起草问卷：第一个调用模型的工具

`/生成 ‹研究需求›`（或“帮我出一份……的问卷”）用你自己的模型服务起草问卷，走托管项目的提案接口（`components/agent/generation.tsx`）：

1. 未登录时只提示登录，不发任何请求。
2. 双线确认卡：可改的研究需求、保存到哪个项目（默认是这段对话所属的项目）、用哪个具备问卷能力的模型服务（默认是输入框里选中的）、发送范围。按“起草（y）”之前不调用模型。
3. 先读项目当前问卷版本，再以 `prepareQuestionnaireGeneration` 生成带幂等键的请求，提交到 `/api/projects/{id}/proposals`；回执须与原请求的服务、版本一致。
4. 服务端在调用模型前明确拒绝的，标“没有启动”；其余失败都按“结果尚未明确”处理并保留原请求，“核对原请求”只重放同一请求（同一幂等键），不会产生新的模型费用。
5. 成功后给出模型提案卡：题干用青色（生成、未核实）。可“带入问卷设计审阅”（在右侧打开问卷设计，确认应用后才成为设计）、在项目中打开或下载 JSON。回复总是回到发起它的那段对话，即使用户已切到别处。

## 对话方式：指令模式与模型对话

输入框的模型菜单里有两种对话方式，默认是指令模式；选择按身份记住（账号记在本浏览器，访客只记在本标签页）。

**指令模式**不调用模型：`lib/agent/router.ts` 是确定性路由，只听懂命令和常用说法。
- 命令：`/下一步` `/照度` `/盲区` `/来处 ‹图表编号›` `/结果 ‹标题或方法›` `/写入` `/写报告` `/起草 ‹章节›` `/生成 ‹研究需求›` `/查 ‹词›` `/夜` `/昼` `/清空` `/经典` `/帮助`，以及每个模块一个打开命令（`/全景` `/问卷` `/抽样` `/分析` `/报告`…）。
- 常用说法：“下一步做什么”“问卷还缺什么”“打开数据分析”“登记了哪些结果”“把结果写进报告”“写报告”“帮我写研究背景”“什么是设计效应”“切换到浅色模式”。
- 一句话涉及两个模块时请用户先选一个；读不懂的长句直说听不懂；概念问题从知识镜原文照录定义、公式（KaTeX）与出处，不改写。

**模型对话**用你自己启用了「研究」能力的模型服务回答（`POST /api/agent/turns`，后端 `multi_agent/agents/research_agent/services/agent_chat.py`）：
1. 每段对话的第一句先出双线确认卡，写明发送什么（这句话、最近 12 条对话、项目照度 / 盲区 / 可回溯图表的摘要、已登记结果与发现的数量；模型请求时，还有已登记结果的标题、方法、有效样本、主要统计量与提醒，以及已确认研究发现的标题与解释）、不发送什么（问卷、原始数据与报告正文）、费用由谁承担；确认后这段对话不再询问。以 `/` 开头的命令始终在浏览器里执行。
2. 后端先记下这一轮（幂等键、输入指纹、限流每小时 30 次、同时只有一轮在跑），再调用模型；回执可以用 `GET /api/agent/turns/{id}` 读取，读取永远不会再次调用模型。
3. 模型只能回答文字，并请浏览器执行清单里的工具，最多 3 个：下一步、照度、盲区、来处、已登记结果、写进报告、打开模块、查知识镜、起草问卷。工具由 `toolTurn` 按对应命令的方式执行，结果是同样的工具卡；写进报告与起草问卷仍从各自的确认卡开始。清单以外的请求丢弃并说明。
4. 回答标“未经核实”，项目里的数字以工具读到的为准。调用前就被拒绝的（服务没有研究能力、版本变化、限流等）说明原因并可再问；结果不明的显示“核对回执”。
5. 多步：只读工具（下一步、照度、盲区、来处、已登记结果、查知识镜）的结果会自动发回模型（`step` 与 `toolResults`），让它引用实际数字接着回答。一句话最多调用 3 次，最后一步后端不允许再请求工具；同一句里重复请求的工具不再执行，没有新结果时循环自然结束。打开模块与起草问卷不会触发续答。

会改动的动作（删除对话、调用模型、起草问卷、写进报告、起草报告章节）都先出确认卡。

顶栏的“导出对话记录”把当前对话存成 Markdown（`lib/agent/transcript-export.ts`），可作 AI 使用说明的附件：
- 开头写明本段对话调用模型的次数与服务，其中结果尚不明确的有几次。
- 每次调用在发出时就记在消息上（服务、步数），随后记下结局：完成、失败、结果不明，或没有发出。没有发出的（服务在调用模型前拒绝、回执查无此轮、起草在发出请求前停止）照常列出，但不计入次数。
- 逐条标出模型回答（未经核实）、平台按规则给出的回答、每次确认的结果；起草问卷的确认内容与模型拟议的题目一并列出。公式保留 TeX。
- 它只覆盖这段对话在本浏览器里保存的内容，不是完整的 AI 使用台账；报告的“AI 使用记录”附录另从服务端回执整理问卷提案。

## 视觉语言

默认浅色，大量留白；深色主题由图标栏切换。颜色只表达证据状态：金 = 有来处的数字，青 = 生成未核实，青绿 = 方法、命令与焦点，红 = 仅用于错误。镜室的意象只作点缀：照度条、状态符号、回溯时的金色光路；新回复里的金色数字会“显影”一次，减弱动效时退化为静止。
