# 证见 Agent 记忆与过程连续性总体规格

- 状态：Proposed（待审）
- 日期：2026-10-29
- 范围：整个 Agent 系统的记忆分层、过程账本、上下文编译、恢复与审计
- 关系：本文件是总体设计；[项目记忆规格书](2026-10-29-agent-memory-design.md)是其中第 3 层的第一个实现切片；PR #50 已落地该切片的内容核心
- 规范性用语：**必须**（must）、**应该**（should）、**可以**（may）

---

## 1. 一句话与“不会丢失”的定义

证见的记忆不是更长的聊天记录，也不是一个向量库，而是：

> **一份不可变的过程账本 + 若干可重建的记忆投影 + 一个受预算约束的上下文编译器。**

“不会丢失”在本规格中不是一句口号，而是五条可验收的不变量：

1. 用户说过的每一句话、模型的每一次请求与回执、每一次工具调用与结果、每一次记忆提议与确认，都有不可变事件。
2. 每个已完成的回合都有检查点；刷新、崩溃、换设备后可以从检查点继续，不重放模型、不重复计费。
3. 过程账本可以重建任意回合的上下文清单（模型当时看到了哪些记忆、证据、历史、工具结果）。
4. 项目事实、决策和证据有版本与来源；底层变化只标失效，不静默改写。
5. 任何删除都是用户明确发起的删除；系统自身不做静默清理，导出可带走完整过程。

不承诺的部分也必须说清：用户主动删除、账号被删除、浏览器本地数据被系统清除、设备损坏，属于用户或平台层面的删除/丢失；系统提供导出与备份入口，但不能违背删除权去“偷偷留一份”。

## 2. 背景与现状

| 现在有什么 | 缺什么 |
|---|---|
| 浏览器线程（`threads.ts`），按身份保存最近 12 条进入模型 | 跨设备、跨对话的完整过程；线程只在本浏览器 |
| 模型回执 `Operation`，幂等、可核对 | 回执不是过程账本；没有工具、记忆、上下文清单的因果链 |
| 项目模块的事实源：问卷、数据、结果、报告、规则 | 这些事实没有统一的过程引用，也没有和对话事件串起来 |
| 项目记忆（PR #50）：意图、决策、开放问题、版本、服务端简报 | 证据索引、失效、提议、确认、过程视图；个人记忆与会话压缩尚未接入 |
| `chatContext` 摘要与 `memory.read` 工具 | 没有记录“模型这一轮具体看到了什么”的清单；上下文无法逐轮重建 |

如果只做“更长的上下文”，结果是：模型看到的更多，但**过程仍然不可恢复、不可审计、不可解释**。所以本规格把“过程”作为一等公民，记忆只是过程的可读投影。

## 3. 总体架构

```
┌────────────────────── 事实源（Source of Truth）──────────────────────┐
│ 选题版本 · 规则快照 · 问卷版本 · 数据指纹 · 登记结果 · 报告版本 · 回执 │
└──────────────────────────────┬───────────────────────────────────────┘
                               │ 只引用，不复制
┌──────────────────────────────▼───────────────────────────────────────┐
│                        过程账本（Append-only）                        │
│ 用户消息 · 模型请求/回执 · 工具调用/结果 · 记忆提议/确认 · 编辑 · 错误  │
│ 因果链 · 幂等键 · 作用域 · 内容哈希 · 检查点 · 上下文清单             │
└───────────────┬───────────────────────────────┬──────────────────────┘
                │ 投影                           │ 重建
┌───────────────▼──────────────┐   ┌────────────▼─────────────────────┐
│ 记忆投影                     │   │ 上下文编译器                      │
│ 工作记忆（本轮）             │   │ 按预算选择、裁剪、标注来源         │
│ 会话记忆（线程/摘要）         │   │ 生成 ContextManifest              │
│ 项目记忆（确认档案）          │   │ 注入提示词 + 按需工具             │
│ 个人记忆（偏好）              │   └────────────┬─────────────────────┘
│ 知识镜（审核知识）            │                │
└──────────────────────────────┘                ▼
                                              模型
```

**事实源 > 已确认记忆 > 过程事件 > 会话摘要 > 模型推断。** 这一段优先级必须写进提示词，也要写进 UI 的“为什么”。

## 4. 五层记忆与事实源

### L0 事实源（不是记忆）

项目模块的版本化数据：选题、规则、问卷、数据指纹、登记结果、报告、模型回执。它们由各模块自己的流程产生，不能被 Agent 改写，也不进入记忆正文。记忆只能引用它们的 id/版本/哈希。

### L1 工作记忆（单轮）

当前用户消息、当前面板、本轮工具结果、待确认动作、当前临时计划。生命周期是一轮；不持久化。它由事件账本中的本轮事件投影出来。

### L2 会话记忆（线程）

当前对话的消息、最近窗口、将来的本地压缩摘要。默认存在浏览器；登录且归入云端项目的线程**应该**同步“过程事件”到云端（仅线程所有者可见）。摘要只作为会话视图，永不升级为项目事实。

### L3 项目记忆（跨对话、团队）

随托管项目版本化的档案：研究意图、已确认决策、开放问题，以及即将接入的证据索引。云端保存、本地只读缓存；owner/editor 确认，reviewer/viewer 只读；失效只标记、不自动改写。详见项目记忆规格书。

### L4 个人记忆（跨项目、按用户）

用户的研究偏好、常用方法、写作风格、反复纠正。按用户存储，不进入团队项目档案；用户可查看、编辑、删除。默认只影响该用户自己的对话。

### L5 知识镜（共享、审核）

已审核的概念、公式与出处。只读、版本化、由知识维护流程产生；按需检索，不能被 Agent 改写，也不能与项目记忆混在一起。

### 为什么必须分开

- 项目记忆回答“这个项目定了什么”；知识镜回答“方法上通常怎么做”；个人记忆回答“你习惯怎么做”；会话摘要回答“刚刚聊到哪”。
- 混在一起会产生三类事故：把模型猜测当项目事实、把另一个项目的偏好带进来、把未审核知识当结论。
- 分开存储、分开授权、分开失效，是“不会丢失”而不“串味”的前提。

## 5. 过程账本

### 5.1 事件

每个事件必须包含：

```json
{
  "schemaVersion": 1,
  "id": "客户端生成的 UUID",
  "scope": { "kind": "thread|project|user", "id": "..." },
  "seq": 42,
  "type": "user.message|model.request|model.receipt|tool.request|tool.result|memory.propose|memory.confirm|memory.ignore|memory.stale|edit|consent|error|checkpoint|legacy.message",
  "actor": { "kind": "user|agent|system", "id": "..." },
  "at": "2026-10-29T09:42:11Z",
  "causationId": "上一事件的 id，可为空",
  "correlationId": "同一回合/同一句话的 id",
  "idempotencyKey": "写入幂等键",
  "payloadHash": "sha256...",
  "payload": { "引用、摘要或必要文本" },
  "refs": ["memory:revision", "evidence:result:id", "receipt:turn-id"],
  "visibility": "owner|project-members|user"
}
```

- 事件**只追加**，不更新、不删除；纠错用新事件表达。
- `seq` 在 scope 内单调递增；服务端分配，客户端只在本地日志里使用临时序号。
- `id` 由客户端生成，重试不产生重复事件；服务端按 `id` 去重。
- `payload` 不存原始数据行；长文本、文件、图表以内容哈希 + 引用保存。

### 5.2 回合检查点

每个已完成的回合必须有一个 `checkpoint` 事件，包含：

```json
{
  "threadTail": "最后一条消息 id",
  "correlationId": "这一轮的 id",
  "pending": { "consent": null, "toolCalls": [], "memoryProposals": [] },
  "memory": { "projectRevision": 3, "personalRevision": 7 },
  "evidence": { "basis": { "questionnaire": 4, "datasetHash": "sha256...", "report": 9 } },
  "contextManifestHash": "sha256...",
  "resumeToken": "可重新进入的游标"
}
```

检查点让恢复不需要重放全部历史；账本让检查点可以被验证和重建。

### 5.3 上下文清单（ContextManifest）

每一轮模型调用必须记录“模型看到了什么”：

```json
{
  "promptVersion": "agent-chat/v2",
  "model": { "serviceId": "...", "label": "...", "model": "..." },
  "budget": { "contextBytes": 16000, "promptBytes": 40000, "usedBytes": 0 },
  "sources": [
    { "kind": "project-memory", "revision": 3, "hash": "sha256..." },
    { "kind": "thread-history", "messageIds": ["..."], "summaryId": null },
    { "kind": "evidence", "resultId": "...", "revision": 9, "hash": "..." },
    { "kind": "knowledge", "entryId": "...", "version": "..." }
  ],
  "truncation": ["history:dropped 3 oldest", "knowledge:omitted 2 hits"],
  "promptHash": "sha256..."
}
```

- 不要求把完整提示词存进数据库；要求存清单 + 哈希 + 截断记录，能重建的部分可重建。
- 含服务密钥或原始数据的片段不进入清单正文；只记录引用和脱敏标记。

## 6. 写入协议：先落地，再调用

### 6.1 本地耐久日志

- 浏览器用 IndexedDB 保存每个 scope 的事件日志和最新检查点；`threads.ts`/`drafts.ts` 的现有本地存储是兼容层，不替代日志。
- 用户按下发送、确认、编辑或工具结果返回时，**先写本地日志并确认落盘**，再发模型/工具请求。
- 离线时继续写本地日志，标记 `pendingSync`；联网后按 id 幂等同步。

### 6.2 云端同步

- 登录且线程归入云端项目：事件同步到云端，`visibility: owner`（线程内容只给所有者），项目记忆事件 `visibility: project-members`。
- 访客/本地项目：只写本地日志；UI 明确“仅本机，换设备不续”。
- 第一次把线程归入云端项目时，告知“过程会同步到项目（仅你可见）”，并允许改为本地；默认选择记住在该项目/该用户。

### 6.3 写入顺序

1. `user.message` 或动作意图事件落本地；
2. 需要模型时，落 `model.request`（含 idempotency key、上下文清单草稿）后再发出；
3. 回执到达，落 `model.receipt`（引用 Operation receipt id）；
4. 工具请求落 `tool.request`，浏览器执行后落 `tool.result`；
5. 记忆提议/确认落独立事件；
6. 回合结束落 `checkpoint`；
7. 后台同步到云端；失败只影响同步状态，不影响本地过程。

服务端接收事件时按 scope 加锁、分配 `seq`、校验因果和幂等；重复事件返回已存结果，不产生第二条。

### 6.4 不丢的三条硬规则

- **调用前必须有持久化请求事件**：没有 request 事件，不允许发出模型/工具调用。
- **回执必须落账**：即使浏览器崩溃，下一次恢复先查未结算的 request，按幂等键/回执 id 核对，不重复调用。
- **检查点必须覆盖已结算回合**：没有检查点的回合在恢复时由账本重建，并补写检查点；不允许“只存在内存里”的完成状态。

## 7. 读取协议：上下文编译器

### 7.1 每轮信封

编译器按以下顺序组装，超预算时按顺序裁剪；裁剪必须写入 ContextManifest：

1. 系统规则与真相优先级；
2. 项目简报（约 2k 字；项目记忆）；
3. 当前工作记忆（当前消息、当前面板、待确认动作）；
4. 会话记忆（最近消息 + 可选本地摘要）；
5. 本轮工具结果（按需）；
6. 个人记忆（若启用，按用户上限）；
7. 知识镜命中（按需，最多 N 条）。

### 7.2 读取规则

- 项目记忆和证据只读当前项目；个人记忆只读当前用户；知识镜只读审核条目。
- 所有被注入的内容带来源 id/版本；模型可以引用，但不能伪造来源。
- 记忆与事实源冲突：事实源当前版本优先，模型必须指出冲突。
- 超出预算时先丢最旧历史，再减少知识命中，再截断个人偏好；项目简报和当前用户消息不得丢。
- 模型需要细节时用工具：`memory.read`、`knowledge.search`、`evidence.read`；工具结果同样落 `tool.result` 事件。

### 7.3 会话压缩

- 长对话可以生成会话摘要，但摘要是一个派生事件，引用原始事件范围与哈希；
- 原事件不因摘要而删除；
- 摘要只进入会话记忆，不进入项目记忆的有效事实；
- 用户可查看“摘要基于哪些消息”，并可要求重建。

## 8. 记忆生命周期

| 阶段 | 行为 |
|---|---|
| 捕获 | 用户消息、模型回执、工具结果、编辑、确认进入账本 |
| 分类 | 按 scope（线程/项目/个人/知识）和风险（证据派生/文字结论/偏好）分流 |
| 提议 | 文字结论与偏好由 Agent 提议；证据索引自动派生；会话摘要自动生成但标记为派生 |
| 确认 | 项目文字结论由 owner/editor 确认；个人偏好由本人确认或明确编辑；证据索引不需要文字确认 |
| 版本 | 项目记忆、个人记忆、知识镜各自有不可变版本；账本永久保留事件 |
| 使用 | 编译器按预算注入，记录 manifest；回答可追溯 |
| 失效 | 依赖的证据/规则/选题变化 → 标 stale；不自动改写；人类复核或新决策 |
| 归档 | 被取代/撤销的条目保留；当前视图排除；可回看 |
| 删除 | 只有用户明确删除才执行；写 tombstone 事件；同步删除投影；提供导出 |
| 导出 | 线程过程、项目档案、个人偏好、AI 使用记录都可导出；导出包含事件清单 |

## 9. 恢复与“不丢失”场景

| 场景 | 恢复方式 | 验收 |
|---|---|---|
| 发送后刷新 | 本地日志已有 user/model request；恢复读取回执或标未决 | 输入不丢；不重复计费 |
| 模型回答中崩溃 | 检查点/请求事件存在；按 idempotency key 查回执 | 不出现永久“正在回答” |
| 工具执行中崩溃 | `tool.request` 已落账；恢复时提示重试或标未执行 | 不重复执行写操作 |
| 浏览器离线 | 本地日志继续；UI 标“待同步”；联网后幂等同步 | 不丢事件，不串顺序 |
| 换设备 | 云端线程事件 + 检查点；首次打开时恢复 | 历史/决策/过程可见 |
| 模型服务被删除/更换 | 旧事件保留；新调用换服务；manifest 记服务版本 | 旧过程可审计，新调用不继承错误 |
| 两个标签页同时写 | 事件 id 去重、scope 内 seq 合并；检查点取最新 | 不覆盖、不丢一侧 |
| 旧版本线程升级 | 把现有消息导入为 `legacy.message` 事件；不伪造模型/工具事件 | 旧对话不消失；明确标记 legacy |
| 记忆冲突 | 不自动合并；展示冲突；用户选择/新决策 | 不静默覆盖 |
| 用户删除 | tombstone + 投影删除；导出入口保留在此之前已导出的副本 | 尊重删除权 |

## 10. 界面：让过程“看得见”

### 10.1 Agent 过程视图

在对话顶部的“过程”入口打开时间线：

- 按回合分组：用户问 → Agent 计划 → 模型调用 → 工具调用/结果 → 记忆提议/确认 → 回答 → 检查点；
- 每步显示：类型、摘要、时间、来源、状态（完成/未决/失败/失效）；
- 展开可见：ContextManifest、工具结果、记忆 diff、回执 id；
- 提供“只读重放这一轮”：重建上下文与结果，不调用模型、不执行工具；只读展示；
- “从这里继续”只对当前线程开放，并生成新的分支/线程，不覆盖原过程；
- 全程标明“过程已同步 / 仅本机 / 待同步”。

### 10.2 记忆检查器

- 项目记忆：项目页“项目档案”标签（已实现）；
- 个人记忆：个人设置页，按用户可编辑/删除；
- 会话摘要：线程内可展开“摘要基于哪些消息”；
- 每条记忆显示 scope、状态、来源、版本、stale 原因、确认人；
- 支持导出与删除；不提供“模型自动改写”。

### 10.3 线程导出

现有 Markdown 导出扩展为“过程记录”：

- 对话正文 + 每轮检查点摘要 + 模型调用清单 + 工具结果 + 记忆变更 + ContextManifest 摘要；
- 用户可只导出对话，也可导出完整过程；
- 导出文件明确标注哪些内容来自模型、哪些来自项目事实、哪些是提议。

## 11. 服务端与客户端组件

### 11.1 服务端

| 组件 | 职责 |
|---|---|
| `agent_events` 表 | 追加事件、scope 内 seq、幂等、visibility、payload hash |
| `agent_checkpoints` 表 | 回合检查点、contextManifest hash、resume 游标 |
| `agent_turns` / `Operation` | 模型调用回执；被事件引用，不重复存 |
| `project_memory_*` | 项目记忆版本与提议（已有规格） |
| `personal_memory` | 个人偏好版本（后续） |
| `ProjectProcessService` | 追加事件、同步、恢复、只读重放 |
| RLS | 线程 owner、项目成员、个人用户、知识公开范围 |

**接口草案**：

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/agent/events` | 幂等追加一批事件；服务端分配 `seq`、校验 scope/visibility |
| GET | `/api/agent/process?scope=thread:{id}` | 过程时间线（分页） |
| GET | `/api/agent/checkpoints/latest?scope=thread:{id}` | 恢复游标与最新检查点 |
| POST | `/api/agent/checkpoints` | 写入回合检查点；服务端同时可在结算时自动补写 |
| GET | `/api/agent/context-manifests/{id}` | 只读查看某轮上下文清单 |
| DELETE | `/api/agent/threads/{id}` | 用户明确删除；写 tombstone 并清理投影 |

约束：同一 scope 内 `(scope, seq)` 唯一；同一 client event `id` 唯一；事件 `UPDATE/DELETE` 禁止；检查点不可修改；线程事件只允许 owner 读写，项目记忆事件按项目角色授权。

### 11.2 客户端

- `agent-journal`（IndexedDB）：本地事件、检查点、待同步 outbox；
- `useAgentProcess`：读取/恢复/同步/重放状态；
- `AgentProcessView`：时间线与检查点；
- `ContextManifestView`：这一轮模型看到什么；
- 现有 `threads.ts`/`drafts.ts` 继续作为输入与草稿的本地层；升级时导入为 legacy 事件；
- 现有 `AgentShell` 的发送/工具/确认路径统一走“先写 journal，再调用”。

### 11.3 与现有回执的关系

- `Operation` 继续负责模型调用的幂等与计费；
- 事件账本记录“为什么发、发了什么、什么时候、结果引用哪个回执”；
- `GET /api/agent/turns/{id}` 仍只读回执；恢复时先读事件/检查点，再按需读回执；
- 不允许用事件账本替代回执去重新调用模型。

## 12. 隐私、保留与安全

- **线程事件**：默认仅 owner 可见；归入云端项目时同步，但队友看不到私人对话正文，只看到项目记忆/证据事件。
- **项目记忆事件**：项目成员按角色可见；写入仅 owner/editor。
- **个人记忆**：仅本人；不进入项目简报。
- **知识镜**：按现有审核/发布范围。
- **原始数据**：不进入事件 payload；只存哈希、行数、引用。
- **保留**：项目记忆与审计事件随项目保留；线程事件保留到用户删除/账号删除；系统不做自动静默删除。压缩摘要不删除原事件。
- **删除**：写 tombstone；删除投影与缓存；保留必要的删除审计（不含正文）。
- **导出**：用户可导出自己的线程过程、项目档案与个人偏好；导出是“不会丢失”的最后一道保险。
- **密钥**：事件账本不得包含模型密钥；写入前做敏感扫描。

## 13. 测试与验收

必须覆盖：

1. **事件完整性**：每种动作都有事件；没有无事件的模型/工具调用。
2. **崩溃注入**：在请求前、请求中、回执后、工具中、检查点前分别杀进程；恢复后不重复计费、不丢消息、不出现永久加载。
3. **重放一致性**：从检查点重建 ContextManifest，哈希一致；重放不调用模型/工具。
4. **并发**：两个标签页同时写同一线程；事件不重复、不覆盖；检查点取最新。
5. **离线/跨设备**：离线写本地，联网同步；换设备恢复。
6. **权限**：线程 owner、项目角色、个人记忆隔离；越权 404/403。
7. **失效**：问卷/数据/报告/规则变化后旧决策标 stale，不自动改写。
8. **压缩**：摘要引用原事件；原事件仍在；摘要不进入项目事实。
9. **旧线程导入**：legacy 事件可导出、可查看，不伪造工具调用。
10. **删除**：删除后投影/缓存不可见；导出入口仍可用；审计不含正文。

验收标准：任一回合都能在过程视图里还原“问了什么、模型看到什么、做了什么、改了什么、结果是什么”；刷新/换设备/换模型后不丢；没有来源的数字/结论不进入项目记忆。

## 15. 决策记录

| 决策 | 选择 | 理由 |
|---|---|---|
| 记忆形态 | 过程账本 + 投影，不是单一向量库 | 可恢复、可审计、可解释；符合证据链 |
| 事实源 | 项目模块/回执为准，记忆只引用 | 避免模型把摘要当事实 |
| 项目记忆 | 云端版本化 + 本地缓存 | 团队/设备共享，原始数据仍留在浏览器 |
| 会话记忆 | 本地优先，云端项目线程 owner 级同步 | 不丢过程，同时不把私人对话暴露给队友 |
| 写入 | 先写 journal，再调用；文字记忆确认 | 崩溃可恢复，模型不能静默写 |
| 失效 | 依赖变化标 stale，不自动改写 | 保留人的判断与审计 |
| 压缩 | 摘要引用原事件，不删原文 | 不丢内容，不把摘要升格为事实 |
| 个人/项目/知识 | 分开存储与授权 | 防止串味与越权 |
| UI | 过程时间线 + 记忆检查器 + 项目档案 | 让“不丢失”可见、可审 |
