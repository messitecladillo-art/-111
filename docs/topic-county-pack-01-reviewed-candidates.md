## 离线重建与验证

在任意干净检出的源代码工作树根目录运行。构建器默认读取与脚本同目录的 `review-first-candidates.json`，不再要求 `--review`；该参数仍可指向字节一致的副本，并接受同一固定 SHA-256 检查。

```text
python -B -X utf8 corpus-source/topic-advisor/county-pack-01/build-reviewed-candidates.py --self-test
```

Linux/macOS 通常将首个命令名换为 `python3`。数据测试沿用仓库约定：可选 `EVIX_PYTHON`，未指定时 Windows 使用 `python`、其他平台使用 `python3`。没有必须设置的机器路径变量。路径根据脚本自身位置解析，工作目录无需指向主工作区。

默认只检查候选 JSON 是否逐字节等于确定性派生结果。`--self-test` 同时在内存中对三份输入各追加一个换行，检查三次均被哈希漂移保护拒绝，并重复派生比较字节一致性；不改动输入文件。需要重新生成时显式增加 `--write`，它只写新候选 JSON；`--stdout` 则只输出候选 JSON。

原二十县包历史字节使用 UTF-8、CRLF；其构建器现在显式输出该行尾，保持 `a7c99603…`，不再依赖 Windows 的隐式换行转换。候选包继续使用 UTF-8、LF，保持 `59a23fad…`。数据测试在临时干净目录中运行默认候选检查，并拦截原构建器写入到内存，比对完整输出字节及历史哈希，绝不覆盖真实父包。

干净检出必须包含下列输入；仅添加新候选 JSON 和脚本并不足够：
