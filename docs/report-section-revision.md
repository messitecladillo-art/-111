# 报告章节原位修订

报告纸面的右侧「章节修订」处理当前选中的章节。顺序为：选择章节 → 核对发送范围与依据 → 确认调用个人报告模型 → 比较生成前原文和候选 → 采纳或保留原文。无需离开报告，也不另建一份编辑器。

章节导航按浮动工具栏的实际高度定位，避免标题和开头段落被遮住；系统减少动态时直接定位。

## 职责与数据流

| 位置 | 职责 |
|---|---|
| `components/agent/SectionRevision.tsx` | 展示确认、原文／候选、依据、调用状态；只发出用户操作 |
| `components/agent/useSectionRevision.ts` | 冻结请求、用户确认、真实请求／回执、会话隔离、未知结果处理 |
| `lib/agent/section-revision.ts` | 生成最小请求、绑定输入、校验回执、保护原文与非正文对象、纯内容转换 |
| `components/EviXPlatform.tsx` 的 `useWorkbenchModules` | 将数据／设计／待交接输入版本和实际编辑器控制器连接起来；再次核对登录身份 |
| `components/editors/EditingStudio.tsx` | 读取同步内容、核对版本与编辑权限、实际采纳；复用既有撤销历史 |
| 现有 `/api/agent/drafts` | 按同一个幂等标识记录调用和返回回执；本批不新增后端接口 |

请求只含所选章节的正文段落、课题名称与目标范围、已登记事实摘要及已确认发现。不会自动发送其他章节、原始答卷或完整数据。确认面板展示实际冻结的原文和依据；事实数字继续通过既有占位符合约填入，模型自己写入的数字或未知事实引用按现有解析规则丢弃。

## 采纳的条件

候选绑定账户、登录 epoch、会话、项目、实际编辑器版本、精确章节快照及研究依据。数据、设计或待交接输入变化会产生新的输入标识。章节正文、标题、来源、对象、登记结果、研究发现或文献版本变化，均使旧候选不能采纳。报告发生编辑或撤销后也需重新准备候选。

这些条件分别在发送前、候选操作时和实际编辑器写入前核对。最后一处使用编辑器同步 `current`，不使用延迟的展示状态。账户撤销和报告生成活动也读取同步控制器；整篇报告生成期间不能采纳章节修订。

只有编辑器明确返回成功，界面才显示「修订已采纳」。一次采纳加入一个撤销步骤；重复点击和撤销后的旧候选均不能再次写入。采纳后，现有写作检查根据更新后的正文重新计算；这是内容完整性检查，不代表统计正确、研究结论已验证或赛事 Gate 通过。

## 保留与限制

- 图、表、公式、引用说明块、重点说明块、来源、稳定 ID 和其他章节保持不变。新段落按原正文槽位分配，保留非正文对象之间的顺序；排版仍需用户检查。
- 教学模拟声明原样保留。正文中的行内引用或公式若被候选遗漏，拒绝采纳，并提示在编辑器中人工处理。
- 首批处理单节至多 3,000 字、最多八个返回段落。长章节先拆分，不静默截掉原文。
- 「停止等待」只停止本地等待，不宣称取消远端或免除费用。未知结果只能查询原请求回执，不自动重新生成。切换会话永久解除旧候选的写入资格。
- 候选保留在当前页面会话内；本批不提供候选跨刷新恢复、云端候选版本库或任意文字选区的逐字修订。已采纳内容沿用报告既有保存行为。
- 本批没有改变既有报告草稿的账户级缓存范围，也没有把画布或网页写作操作连接为赛事 CLI 阶段推进。

## 验证入口

`tests/section-revision.test.mjs` 检查精确输入、来源与对象保留、版本漂移、跨会话、回执绑定和行内引用保护。`tests/report-readonly.test.mjs` 直接运行实际编辑器回调，覆盖中文输入组合、一次采纳、撤销、重复采纳、同步编辑与撤权。

浏览器验收使用独立配置的合成账号与拦截传输，验证真实 `/agent` 界面的确认、比较和编辑操作，不调用付费模型。真实服务费用、模型质量、生产权限和跨团队并发不由这些检查证明。
