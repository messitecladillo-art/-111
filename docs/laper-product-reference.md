## 1. 结论

最值得参考的是工作区的组织方式：作品居中、结构在左、当前工具在右、AI 按需出现。内容、结构、资产与任务分别有入口，又围绕同一个项目互相定位。界面不要求用户先理解所有工具。

证见应学习这种协作关系，把研究问题、调查设计、问卷、数据、分析结果、研究发现和报告连接起来；保留自己的研究契约和视觉识别。Anatomy 机制图作为实际任务的屏幕反馈，嵌入当前工作位置，不建设一个需要用户切换状态的独立展示区。

## 4. 转化为证见的界面规则

| 观察 | 证见规则 | 对应对象/位置 | 必须保留的研究约束 |
|---|---|---|---|
| 新建入口集中 | 一个明确输入起点，少量任务快捷入口 | 研究问题、导入资料、继续项目 | 不以“开始”代替调查设计确认 |
| 作品占据中心 | 报告、数据、问卷是当前工作对象，AI 占辅助位置 | 现有 AgentShell、编辑器宿主 | 复用已挂载编辑器，不复制另一份文稿 |
| 左结构、右工具 | 左侧定位章节/问题，右侧展示当前对象的属性和检查项 | ReportNav、ReportInspector、模块面板 | 不在一个底部小弹窗堆全部设置 |
| 多视图复用对象 | 图、表、代码和画布围绕同一登记结果展示 | OutputPanel、ResultSnapshot、画布引用 | 视图切换不重算、不改变分母 |
| 模块工具规律相同 | 面板、搜索、排序、定位的布局和术语统一 | 问卷、资料、数据、图表 | 只显示真实可执行能力 |
| AI 可以停靠 | 助手可收拢，任务信息出现在正在工作的上下文 | 对话区、报告空白、分析读取、知识检索 | 不能用装饰动画假装计算或核验完成 |
| 工具步骤可追踪 | 明确显示排队/等待、返回、失败、未知；结果可定位 | AgentTaskExecution、前端调用记录 | 回执和产物需对账，不能靠模型一句“成功” |
| 附件有来源 | 区分项目资料、聊天附件、外部来源与生成资产 | 知识资料、证据来源、视觉素材 | 原始答卷、作品及密钥不自动外发 |
| 顾问有方向 | 不同角色拥有明确工具与输入输出 | Research/Survey/Data/Writing/Reviewer | 角色被选中不等于实际执行；Reviewer 不能自审 |
| 导出先范围后格式 | 先选正文/附录/证据材料，再选排版与格式 | 现有报告导出链 | 适用赛事规则、匿名和来源检查优先 |

## 5. Anatomy 本批的融合范围

本批只处理已有过程反馈，不借调研之名重写工作区或后端：

1. 报告流：继续使用实际章节流回执，在当前纸面空白或页外紧凑区域反馈；不参与排版测量和正式导出。
2. 对话：知识加载和当前模型请求使用内嵌装置；模型尚未回执时显示“等待返回”。历史 running 记录不被当作本页活跃请求。
3. 数据分析：仅真实文件读取/校验期间显示对应状态，不把本地同步统计包装成长期后台任务。
4. 知识检索：以当前账户、本次提交及查询回执驱动；排队和结果未知保持静态。
5. 删除独立 `/examples/report-workstation` 产品路由；自动状态反馈不提供手动状态切换或“结构查看”按钮。内部测试夹具与产品入口分开。

前三项更大的产品改进另成小批：明确当前上下文范围；对原文显示提案差异并绑定目标版本；让目录、审阅问题和成果引用互相定位。此处属于建议，尚不宣称完成。
