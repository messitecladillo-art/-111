# 数据分析双入口方案

日期：2026-10-10。状态：首批双入口与文件方案已实现，验收见 [工作区记录](research-workspace.md)。共享派生变量、依赖图执行器、云端分析计划及拖拽画布仍为后续设计。

## 本批实现

- 在同一份分析方案中提供“选择研究路线”与“自由搭建”；三条路线预览后追加，不覆盖已有模块，12 个模块容量不足时整组不添加。
- 六类现有分析与“信度与题项诊断”共用模块目录；可调整顺序、改分支名称、移除与撤销。路线切换和位置调整保留结果。
- 每个模块可选择一个分类变量及多个纳入类别作为样本分支。路线中的特定人群节点默认要求完成筛选，不能静默按全样本运行。
- 问卷目标列与筛选列均在原始表上检查跳题资格，再与类别筛选取交集。输出保留原始记录、分支人数、共同应答范围、完整有效样本四级口径。
- 保存和导入 `analysis-plan/v1` 文件，保留模块配置、变量、筛选和路线版本；不含原始答卷、计算结果或批准状态。导入先预览、再确认，读取或预览期间发生的新编辑不会被覆盖。
- 恢复严格核对 CSV 哈希、解析指纹、列名、缺失代码，以及原方案的问卷对应和跳题策略。关联问卷的方案需先恢复并确认同版对应；导入不会替用户批准对应。
- 使用自定义分支的计算结果可以下载，但暂不进入报告候选；报告证据契约扩展筛选条件及分母后再开放。未筛选的频数与 α 继续沿用现有候选流程。

当前保存是明确的方案文件下载。刷新后先读取原数据和相同设置，再打开方案并重新计算；本批没有浏览器自动保存答卷或云端分析同步。

## 产品决定

以下为完整目标架构与后续设计。本批实际交付以上方“本批实现”为准；图形连线、个人/团队模板库、云端恢复结果及派生变量依赖尚未开放。

提供 **选择研究路线** 与 **自由搭建** 两个入口，共用一份分析计划。路线是预先组合好的模块和分支，用户可以增删、替换、重排；自由搭建从空白开始，也能插入已保存的路线片段。两个入口切换时保留同一份参数、结果和版本。

路线按研究目标命名。每个模块说明三个问题：它回答什么、需要哪些数据、会产出什么。用户能够查看和修改推荐理由，确认后再加入计划。

## 三类初始路线

依据项目已有三份作品解析，提炼如下产品路线。本轮使用已有来源登记和案例审计，未重新通读原始文件或复算作品原始数据；下列路线是我们的设计。

| 路线 | 主线 | 主要分支 |
|---|---|---|
| 活动体验与运营改进 | 管理问题 → 人群与参与状态 → 体验/需求 → 群体比较 → 改进优先级 → 行动 | 参与者分析体验；未参与者分析障碍；学生/居民等身份可交叉分层 |
| 人群分层与服务支持 | 对象边界 → 经历与需求 → 测量检查 → 可选分群 → 群体差异 → 支持措施 | 按职业、经历或资格筛选；分群须有区分度、稳定性和可解释性检查 |
| 消费体验与增长机会 | 经历筛选 → 品类/体验/痛点 → 复购与推荐 → 改进方案 | 未参与者看进入障碍；参与者看体验；复购意愿与推荐意愿分别分析 |

每条路线区分必需、可选和条件触发节点。节点根据问卷与数据适配：成对需求题可进入 KANO；真实追踪或事件数据可进入时间转化分析。横截面调查的意愿和群体差异按其实际含义呈现。

三条路线共享“研究问题 → 对谁成立 → 用哪些证据回答 → 如何影响决策”的结构。案例中的方法参数、输入和先后关系没有明确记录时，须在实例化过程中重新定义。

## 模块库与组合

| 模块组 | 内容 |
|---|---|
| 数据准备 | 变量字典、样本筛选、缺失处理、反向计分、派生变量 |
| 样本与现象 | 频数比例、数值分布、分组描述、交叉分析 |
| 测量质量 | 内容与题项依据、内部一致性、题项诊断、因子适用性、EFA、CFA/测量模型、构念计分 |
| 关系与解释 | 差异检验、相关、OLS、Logistic、模型诊断 |
| 人群与需求 | 聚类、分群比较、KANO、优先级分析 |
| 研究输出 | 图表、结论记录、适用范围、行动建议、报告引用 |

此表为目标模块库，不代表全部已有计算引擎。当前能力见 [工作区验收](research-workspace.md)。

每个模块保存输入角色、参数、输出类型、版本和适用条件。用户可以保存“某一套分析组合”为个人或团队模板，保存时固定模板版本；更新模板不会自动改写已有项目。

信度与效度模块应细分。α 和题项诊断检查内部一致性；KMO/Bartlett 提供因子分析适用性信息；EFA、CFA 和内容依据分别提供不同证据。问卷中的人口学分类、客观数量和构念题项使用各自适用的方法。删题、维度选择和计分规则作为可审阅决定保存。

## 自由编排与执行依赖

呈现顺序、画布位置和报告顺序由用户调整；实际计算遵循输入依赖。独立分支可以同时运行，下游只在所需上游版本可用时运行。

```text
确认的数据、字典与样本口径
  ├─ 人口学描述 ──────────────────┐
  ├─ 构念题项 ─┬─ 信度与题项诊断 ─┐│
  │            └─ 结构检查 ───────┴─ 测量复核 → 得分定义 → 关联/回归
  └─ 体验变量 → 分组比较 ──────────┤
                                  结果 → 结论复核 → 报告/行动
```

这是候选组合，具体连线由实际使用的输入决定。α 与结构检查可在适用时并行；量表得分被回归引用时，得分定义形成真实依赖。

例如把回归卡片拖到顶部，可以改变它的展示位置；缺少所引用的得分变量时，卡片显示缺失输入，并提供连接入口。错误类型、环路和缺少必需输入会在运行前被指出。

## 界面

入口只显示两个主选项。进入后延续现有简洁工作区：左侧为模块目录，中间为分析计划与当前任务，右侧按需展开参数、依据和检查。

- 默认使用步骤列表与分支摘要，选中一项才展开详细设置。
- 图形视图提供连接、拖动、自动整理和分组；与列表视图共享计划。
- 手机上使用列表与上移/下移，桌面提供拖拽与键盘操作。
- 单个节点分别显示计算状态和复核状态，运行完成后可预览结果、检查口径、批准进入结论。
- 报告引用节点结果；图表和结论保留数据版本、分母与适用范围。

## 工程方案

`AnalysisPlan` 保存计划；`AnalysisNode` 保存模块配置；`AnalysisResult` 保存不可变结果引用；`ClaimRecord` 保存结论与批准。节点最少包含：

```text
id / methodId / methodVersion / researchQuestion
inputs / parameters / dependsOn
executionState / resultRefs / reviewState
```

位置和展示顺序另存 `layout`。路线实例绑定 `templateId/templateVersion`。托管项目的计划与修订最终通过 FastAPI 存入 PostgreSQL，文件沿用私有对象存储；本地工具保留可导出的计划文件。大计算接入任务队列后，执行进度与业务状态分别管理。

结果签名绑定数据、解析设置、变量定义、样本范围、缺失规则、参数、上游结果和引擎版本。修改量表题项会使相关诊断、得分及其模型进入待重算状态；不依赖它的人口学描述继续有效。移动位置、颜色或展示顺序不触发重算。晚到结果保存到它所属的输入版本，旧结果可比较但不能作为新版本结论的依据。

## 分批实现与验收

1. **统一节点协议**：注册现有六类分析及 α，补计划保存、版本、依赖检查和结果引用，迁移已有卡片。
2. **双入口与三条路线**：实现路线预览、数据适配、空白搭建、节点增删和组合模板；未实现引擎的节点明确标为计划项。
3. **补齐统计能力**：差异/相关推断、效应量、区间和诊断，逐步加入 EFA、OLS/Logistic、K-means；复杂模型分别验收后开放。
4. **增强画布**：在依赖与恢复正确的基础上加入拖拽连线和自然转场。

完整目标的验收重点：两个入口操作同一份计划；刷新恢复参数与结果；移动节点不重算；上游改变只使相关后代失效；分支分母可追溯；缺少输入不能运行；任务恢复不重复提交；结论引用当前批准结果。所有新增数值方法使用独立参考实现与公开数据对照。
