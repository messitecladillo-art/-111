# 三维展示与实时文字排版

## 先选择空间表达

| 用户需要 | 可评估方案 | 边界 |
|---|---|---|
| 插画叙事、轻微视差、显影 | 对齐图层、位移与遮罩 | 不能当作可任意绕看的模型；新角度需要素材 |
| 不同角度观察物体细节 | 真实模型与相机控制 | 资产、加载、GPU 开销、输入冲突与回退 |
| 三维主体与长文字共处 | 分离阅读区，或验证过的轮廓避让 | 阅读完整性优先；避让不是相机控制库自带能力 |

沿用已有图形能力，不强制 Three.js、Blender 或 Pretext。普通层叠效果不必引入三维渲染器。用户要求模型/文字避让时再选择和验证实现。

## 真实三维

使用实际版本的相机控制 API。OrbitControls 支持旋转、缩放、平移；阻尼或自动旋转按官方机制持续更新。设置观察范围、复位与阅读态，避免交互截获全页滚动。

显示加载状态与失败回退。按模型复杂度、分辨率、纹理和目标设备测试，不从库宣传推导 FPS。退出时清理自身控制器、循环、几何、材质、纹理和渲染资源，区分共享资产所有权。

模型、贴图与字体的使用权独立于代码许可。示例仓库缺模型时不宣称可直接运行；采用用户允许的真实资产或明确占位模型。

## Pretext 与轮廓避让

研究中的特定示例为 feitangyuan/pretext-3d，依赖 @chenglou/pretext。它是分析入口，不是所有排版方案的固定选型。

职责链：`三维可见轮廓 → 黑白掩码 → 文字行带扫描 → 可用槽 → 按槽宽逐行断行 → DOM 定位`。

Pretext 承担测量与断行；投影、排除范围和槽由作者额外实现。示例把行带命中压成最左到最右包络，选一个最宽槽，不会利用所有内部孔洞或左右分离空间。接入时核验作者依赖与当前 API 兼容性。

动态排版保留合理 DOM 阅读顺序、文本选择和剩余内容入口。字体未加载、窄屏、长文本、不同语言或区域耗尽时，回退普通文流或阅读区。计算和像素读取开销实测，不能用上游排版库性能描述证明整个组合流畅。

## 验收重点

检查缺资产、加载失败、复位、触屏/滚动冲突、上下文丢失与弱设备回退，以及遮挡、截断、读屏顺序、选择、字体变化、长文完整性。方案任务交付约束；实现任务实际验证选定方案，未运行项如实保留。
