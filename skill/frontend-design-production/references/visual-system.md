# 视觉体系、信息架构与组件接入

## 把风格变成规则

用当前内容验证参考：同样的标题、图片和数据密度是否还能保持阅读顺序？把“极简、瑞士、编辑、玻璃拟态、便当盒”等标签拆成网格、对齐、字号、行宽、留白、图文比例与边界。风格可以混合，但要明确谁负责组织信息、谁负责材料和氛围。

| 场景 | 先解决的问题 | 常见适配方式 |
|---|---|---|
| 落地页 | 用户理解价值并进入下一步 | 首屏主张与主操作、证据或产品图、后续节奏；与品牌匹配 |
| 作品集/内容页 | 作品和文字的阅读顺序 | 图片比例、标题层级、章节；作品密度决定卡片或编辑式布局 |
| 工作台/后台 | 状态判断、异常定位、随后操作 | 摘要、趋势、明细与操作分层；筛选和长列表可用 |

这些是信息职责，不是固定模块数量或模板。真实数据不足时用明确的演示数据，不虚构交易、用户、收入或评价来证明产品可信。

## 现有系统优先

读取已有设计变量和组件后，决定复用、扩展或局部新增。改造时不引入第二套颜色、字体或间距体系。新项目可以用语义变量区分正文、次级信息、主操作、表面、边界和状态，再按任务调整值。

把方向应用到有压力的内容：长标题、多行按钮、空数据、错误信息和高密度明细。检查真实标题级别、表单标签、焦点顺序与视觉顺序。对比和字号按产品标准或适用要求核验，不能由“浅色/高级感”推断可读。

渐变、玻璃、发光、纹理和大字号是可选材料。考虑强调层级、背景复杂度与文字对比；连续大面积效果需要有产品理由或明确视觉实验目标。用户选定风格时应把它做好，不用个人默认审美替换。

## 效果组件接入

React Bits 等视觉效果集合可以成为独立零件，不承担完整导航、表单、权限、数据和状态体系。接入时确认：

1. 组件服务于哪个元素和行为。
2. 代码变体匹配当前语言、样式和框架；依赖是否已有，体积和开销是否可接受。
3. 颜色、尺寸、速度、强度接入现有视觉规则。
4. 触屏、键盘、减少动态、重复挂载与清理有可靠行为。
5. 版本与许可适用于当前用途，尤其是再分发组件包、移植库或出售源码。

卡片效果按职责选择：人物视差表现深度，反光表现材质，追光表达局部位置，边框变化提示交互或状态。装饰边框不能冒充真实焦点样式；实际状态不能只靠颜色或动画表达。

## 完成条件

在约定尺寸与内容中，主信息和主操作清楚，规则一致，长内容与状态不会破坏布局。外部资产记录来源与使用条件；灵感截图可用于分析，不能默认变成可商用素材。局部修改只验收相关区域及受影响布局。
