# 上传与批量导入状态

## 两条状态链

区分传输与服务处理，按实际协议描述：

`选择 → 校验 → 排队/传输 → 服务端接收 → 解析/处理 → 可用`

哪些阶段可取消、重试或续传由真实实现决定。没有服务时可以做前端原型/模拟流程，不能宣称已持久化、解析成功或具备真实断点续传。

| 阶段 | 应看到什么 | 完成依据 |
|---|---|---|
| 选择/校验 | 名称、类型、大小、限制与错误原因 | 实际校验；前端不能替代服务端校验 |
| 传输 | 单文件状态、真实或不确定进度、取消 | 传输事件与约定响应 |
| 解析/处理 | 阶段、活动状态、有依据的等待信息 | 服务任务状态或查询/推送结果 |
| 可用 | 可打开或使用的结果、成功/失败明细 | 服务确认且可用的对象 |

XMLHttpRequest.upload 可观察 progress、error、abort、timeout 等；loadend 不区分成功失败。还要检查请求响应与服务协议。传输 100% 不能作为导入成功依据。

## 进度与恢复

总量已知且事件有依据时显示百分比；未知显示阶段与活动状态，避免定时器伪造真实传输进度。剩余时间需有估算数据，信息不足省略；原型模拟进度在交付说明标记。

取消释放本次任务，防止过期完成响应重写成功状态。列表重绘时保持合理焦点：取消或重试后仍可继续操作该文件，移除后到相邻项或选择入口；异步反馈不抢焦点。重试、续传、幂等和去重遵循服务能力；重新发送按钮不证明续传。重复文件按产品规则处理覆盖、重命名或跳过，避免未经授权的破坏性覆盖。

## 批量与文件夹

提供逐文件状态与汇总，允许部分成功并定位原因。明确文件夹入口、平台、类型、层级、隐藏文件与重复项；只把真实支持的范围写为支持。

办公导入可能需要模板、字段映射、预览、错误行；画布导入确认最终对象可用。错误保留可复用输入，允许重试失败项，避免重复成功项。

拖放保留选择文件入口；粘贴、相册、拍照按任务与平台增加。格式/大小/数量限制操作前可见。用合适状态语义通知辅助技术，避免逐帧播报或抢焦点。

## 验收重点

按真实能力测试格式/大小错误、取消、断网、超时、重复、快速重选、部分失败和处理失败。UI 与实际请求/结果一致，过期响应不覆盖新任务；本地模拟不计为真实服务验收。
