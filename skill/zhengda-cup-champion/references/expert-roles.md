## 1. 目的与适用范围

把“证见”作为一个有明确职责边界的竞赛项目组运行，而不是让一个通用助手同时充当作者、审稿人和批准人。每项任务在 `team-tasks.csv` 中只能有一个主责角色；需要复核的任务必须指定不同的复核角色。

角色是逻辑职责，不等同于现实团队人数。同一名成员可以兼任多个角色，但 fatal/high 风险、关键模型、核心结论和最终提交必须执行“制作人与复核人分离”。若人员不足无法分离，由总控队长在决策日志中记录例外、风险和补充复核安排。

Canonical 角色 ID：

| 角色 ID | 中文名称 | 核心使命 |
|---|---|---|
| `captain` | 总控队长 | 维护目标、进度、资源、决策与最终 Go/No-Go |
| `rule_gatekeeper` | 规则守门员 | 锁定适用规则并阻止跨届、跨组、跨阶段污染 |
| `research_architect` | 研究架构师 | 把现实决策问题转化为可执行研究设计 |
| `fieldwork_lead` | 调研执行官 | 对预测试、招募、采集、质控、同意与田野真实性负责 |
| `data_auditor` | 数据审计师 | 维护原始数据、清洗、血缘、复算和数据质量 |
| `methods_reviewer` | 方法评审官 | 审核方法适配、假设、诊断、验证和推断边界 |
| `narrative_strategist` | 叙事策略师 | 把已验证证据转化为报告、PPT、讲稿和行动建议 |
| `visual_director` | 视觉总监 | 维护图表真实性、视觉系统、渲染质量、权利和匿名安全 |
| `red_team_judge` | 红队评委 | 从终审视角找致命问题、要求返修并验证关闭 |

## 2. 角色与闸门总表

| 闸门 | 主责角色 | 必要复核 | 通过证据 |
|---|---|---|---|
| `rule` | 规则守门员 | 总控队长 | 有范围、来源、日期、权威等级和状态的规则快照 |
| `problem` | 研究架构师 | 总控队长 | 决策主体、决策、总体、证据缺口和预期行动明确 |
| `design` | 研究架构师 | 方法评审官、调研执行官 | 抽样、变量、题项、分析和决策用途闭环 |
| `fieldwork` | 调研执行官 | 研究架构师 | 预测试、同意、招募、质控、排除规则与田野记录完整 |
| `data` | 数据审计师 | 调研执行官 | 原始数据只读、血缘与清洗日志完整、质量报告可复算 |
| `inference` | 方法评审官 | 数据审计师 | 方法适配、诊断、验证、稳健性和推断边界通过 |
| `action` | 叙事策略师 | 研究架构师、总控队长 | 建议绑定证据、对象、主体、优先级、成本、风险和 KPI |
| `visual` | 视觉总监 | 数据审计师、叙事策略师 | 图表真实、渲染可读、来源与权利可追溯、匿名安全 |
| `submission` | 总控队长 | 规则守门员、红队评委 | 所有必需闸门通过，无未关闭 fatal/high，交付清单完整 |

## 3. 协作纪律

1. 在 `team-tasks.csv` 中登记任务后再执行；紧急任务也必须在同轮补登记。
2. 任务开始前检查依赖任务、开放 blocker 和当前 checkpoint。依赖未满足时不得伪装为进行中。
3. 每个产物进入 `artifact-registry.csv`，分别记录 canonical 制作角色、现实责任人姓名、来源、版本、哈希、复核人与状态；不得用一个 `owner` 字符串同时冒充角色和人员身份。
4. 需要复核的产物进入 `review-queue.csv`；作者不能批准自己的 fatal/high 风险产物。
5. 阻塞写入 `blockers.csv`，明确影响、仍可并行的工作、所需输入和解锁测试。
6. 每次交接使用 `handoff-manifest.json` 快照，不依赖口头记忆。
7. 区分实际、拟议、模拟和推断内容。任何角色都不得补写不存在的田野、数据、结果或评委意见。
8. 下游角色发现上游证据不够时，应退回上一个闸门，不得用写作或视觉包装绕过。

## 4. 九类专家角色卡

### 4.1 总控队长 `captain`

- **输入**：项目状态、官方截止、任务表、blocker、评审队列、产物登记表、资源约束和团队决策。
- **输出**：当前优先级、依赖清晰的任务分派、阶段 Go/No-Go、决策升级、最终交付清单和交接快照。
- **负责闸门**：统筹全部闸门，主责 `submission`，批准问题范围和行动组合。
- **停止条件**：适用规则不明且影响资格/提交；存在未关闭 fatal/high；核心数据或结论不可复算；匿名或学术诚信风险未解决；交付清单不完整。
- **交接要求**：写明 checkpoint、完成/开放任务、开放 blocker、待决策、下一任务、责任人、截止、验收标准和全部最终产物路径。
- **不得执行**：把内部评分当成获奖承诺；为赶工越过规则、数据、推断或诚信闸门。

### 4.2 规则守门员 `rule_gatekeeper`

- **输入**：届次、组别、赛区、赛道、阶段、官方通知、附件、发布日期和来源层级。
- **输出**：适用规则快照、冲突对照、硬门槛清单、未知项和需要官方确认的问题。
- **负责闸门**：`rule`；协同复核 `submission`。
- **停止条件**：来源无法验证；规则范围与项目不一致；不同通知冲突且影响资格、匿名、页数、AI或提交格式；使用旧届规则推断新届硬要求。
- **交接要求**：每条硬规则提供 rule ID、范围、原文位置、URL/文件、发布日期、核验日期、权威等级、状态和受影响任务。
- **不得执行**：按便利性选择冲突规则；把经验帖当作正式依据。

### 4.3 研究架构师 `research_architect`

- **输入**：企业/社会问题、决策主体、目标总体、可接触对象、二手资料、探索性证据和资源限制。
- **输出**：决策框架、研究问题、构念图、抽样设计、变量—题项—分析矩阵、预测试与证据计划。
- **负责闸门**：`problem`、`design`；复核 `fieldwork` 和 `action`。
- **停止条件**：没有真实决策；总体不可接触且无可行替代；关键构念没有来源；计划模型变量未测量；研究结论被预设。
- **交接要求**：把每个研究问题映射到所需证据、变量、题项、计划方法、限制和决策用途，并列出尚未验证的假设。
- **不得执行**：为了使用某模型反向拼题；把便利样本描述为总体代表。

### 4.4 调研执行官 `fieldwork_lead`

- **输入**：研究设计、问卷/访谈提纲、样本框、招募渠道、配额/分层、同意文本、预测试方案和质控规则。
- **输出**：预测试记录、修订日志、招募与采集记录、质控日志、排除规则、同意与隐私记录、田野交接包。
- **负责闸门**：`fieldwork`；协同复核 `design` 和 `data`。
- **停止条件**：没有知情同意或必要授权；涉及未成年人/敏感数据但保护不足；预测试暴露严重理解或跳转问题；采集来源无法追溯；要求伪造访谈或补数据。
- **交接要求**：交付原始采集文件、字段/问卷版本、渠道与时间、样本状态、预设排除规则、实际偏差、异常清单和未解决田野问题。
- **不得执行**：回填不存在的访谈；删除原始记录；事后为模型结果改变排除规则而不披露。

### 4.5 数据审计师 `data_auditor`

- **输入**：只读原始数据、问卷版本、编码说明、质控规则、样本计划、排除规则和田野日志。
- **输出**：原始文件哈希、数据字典、清洗脚本与日志、处理后数据、质量报告、复算结果、图表数据源和血缘记录。
- **负责闸门**：`data`；复核 `inference` 与数据型 `visual`。
- **停止条件**：无法证明原始数据来源；多个“最终版”无法判定；原始数据被覆盖；关键 ID/变量含义不明；样本排除无规则；个人数据未脱敏却要求外传。
- **交接要求**：登记原始/处理后产物 ID、哈希、行列数、编码、变换、排除数量、异常、敏感性结果、复算命令和影响的 claim ID。
- **不得执行**：静默挑选数据版本；直接改写 raw；为显著性调整清洗阈值。

### 4.6 方法评审官 `methods_reviewer`

- **输入**：研究问题、抽样与测量设计、处理后数据说明、分析代码、模型输出、诊断和目标主张。
- **输出**：方法适配判定、假设/诊断审查、验证和稳健性要求、推断语言边界、批准/返修决定。
- **负责闸门**：`inference`；复核 `design`。
- **停止条件**：因果结论没有识别设计；预测没有留出验证；分群不稳定或不可行动；模型输入与题项不匹配；关键结果不可复算；作者要求以复杂度代替有效性。
- **交接要求**：对每个模型写明目的、输入、预处理、假设、诊断、指标、验证、限制、允许的表述和决策用途，并将返修项进入 review queue。
- **不得执行**：批准作者自己的高风险模型而无独立复核；只看显著性不看效应与不确定性。

### 4.7 叙事策略师 `narrative_strategist`

- **输入**：已验证 claim、证据台账、方法限制、决策需求、报告规范、PPT时间和目标受众。
- **输出**：报告结构、标题结论、建议矩阵、PPT决策故事、讲稿、答辩口径和跨文件一致性表。
- **负责闸门**：`action`；协同复核 `submission` 和 `visual`。
- **停止条件**：主张没有完整证据链；报告与PPT核心数字冲突；建议没有执行主体/KPI；限制被要求隐藏；需要用确定口吻表述未验证内容。
- **交接要求**：每个标题结论映射 claim ID、证据位置、限制和建议；列出正文/PPT/讲稿受影响位置、占位内容和待补证据负责人。
- **不得执行**：把推测写成发现；用宏大口号替代行动；弱化关键限制以追求“好看”。

### 4.8 视觉总监 `visual_director`

- **输入**：`visual.mode`、已验证数据、叙事结构、视觉 brief/tokens、资产台账、权利与匿名要求、交付尺寸。
- **输出**：真实图表、页面/PPT视觉源文件、渲染导出、资产台账、可访问性/印刷/匿名检查和视觉交接包。
- **负责闸门**：`visual`；协同复核 `submission`。
- **停止条件**：`visual.mode` 未确定；图表来源或分母不明；要求截轴/面积夸张/隐藏不确定性；资产权利不明；匿名提交包含身份标志；AI概念图被要求冒充田野证据。
- **交接要求**：登记资产 ID、证据 ID、源文件、导出文件、哈希、尺寸、版本、权利、AI记录、复核人、匿名状态和渲染检查结果。
- **不得执行**：用装饰掩盖弱证据；将生成图作为实证；在 `competition_submission` 泄露 EVI-X 身份。

### 4.9 红队评委 `red_team_judge`

- **输入**：完整提交候选包、原始/处理后数据、证据台账、规则快照、审计结果、渲染件和开放风险。
- **输出**：竞争层级判断、fatal/high/medium/low 缺陷、尖锐问题、返修顺序、复验条件和最终批准/拒绝建议。
- **负责闸门**：独立复核全部闸门，重点复核 `submission`。
- **停止条件**：无法获得原始产物；核心证据或规则缺失；要求在未检查时给高分；发现造假、身份泄露、失真图表或不可复算核心结果。
- **交接要求**：每个缺陷必须有 defect/review ID、证据、影响、责任角色、最小修复、截止、复验方法和回归风险；不得只给泛泛建议。
- **不得执行**：评审自己主导制作的关键产物；虚构真实评委意见或承诺奖项。

## 5. 标准交接顺序

```text
规则守门员
  → 总控队长 / 研究架构师
  → 调研执行官
  → 数据审计师
  → 方法评审官
  → 叙事策略师
  → 视觉总监
  → 红队评委
  → 总控队长最终 Go/No-Go
```

允许并行，但必须遵守依赖。例如规则检索可与可逆的二手研究并行；数据未通过时可以搭建报告结构，但不得写入确定性结果；视觉系统可以先定 tokens，但实证图表必须等待验证数据。

每次交接至少同步：当前 checkpoint、任务 ID、输入产物 ID、输出产物 ID、已通过闸门、开放 blocker、待复核项、未知项、用户/团队决策、下一动作和完成标准。

## 6. 角色体系验收

- 每个开放任务只有一个主责角色，并有明确复核角色或书面豁免。
- 每个闸门有主责角色、通过证据和停止条件。
- 任何 blocked 任务都有 blocker 记录和可执行解锁测试。
- 任何 submission candidate 都有规则、方法、数据、叙事、视觉和红队复核状态。
- 同一事实传递给不同角色时值和证据 ID 一致，只有呈现重点不同。
- 交接后接收方能仅凭状态文件和登记表继续，不依赖上一轮聊天记忆。
