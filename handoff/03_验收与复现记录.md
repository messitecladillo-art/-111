## 接收方验收清单

1. 对外层 ZIP 运行 SHA-256，并与同名 `.sha256` 文件核对。
2. 解压后读取 `PACKAGE_MANIFEST.json`；用 `CHECKSUMS.sha256` 校验包内 payload。
3. 确认不存在 `node_modules`、旧 `dist`、`.env` 或 `.git` 目录。
4. 对 `git-bundles/evi-x-platform.git.bundle` 运行：

   ```powershell
   git bundle verify .\git-bundles\evi-x-platform.git.bundle
   ```

5. 进入网站目录执行 `npm ci` 后复跑 `npm run verify`；不要用单项测试代替统一发布检查。
6. 在 `workspace` 安装 Python 依赖后复跑静态和行为评测。
7. 抽查六份原始作品能否打开；如要公开使用，先取得版权/传播授权。
8. 任何新规则或新案例先补充溯源，再更新产品和 eval。

若 Python 可用，可在解压后从 ZIP 同级目录执行一键校验：

```powershell
python -X utf8 .\正大杯EVI-X-Agent交接包-2026-08-26-r2\handoff-tools\verify_handoff_package.py `
  .\正大杯EVI-X-Agent交接包-2026-08-26-r2.zip
```

## Git bundle 的可选恢复方式

若希望把网站源码恢复成独立 Git 工作树：

```powershell
git clone .\git-bundles\evi-x-platform.git.bundle .\evi-x-platform-from-bundle
Set-Location .\evi-x-platform-from-bundle
git rev-parse HEAD
```

预期 HEAD 为 `8f129ef130f08205324173dbbd336c283c8edec1`，预期分支为 `codex/unify-control-contract`。包内 `workspace/apps/evi-x-platform` 已含可直接安装的源码；bundle 主要用于历史与基线校验。
