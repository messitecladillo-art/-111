## 证据边界

| 层级 | 含义 | 允许用途 |
|---|---|---|
| `official_verified` | 官方公告或可信高校公告能直接证明的字段 | 展示公告可证题名、学校、组别、奖级等字段 |
| `user_attested` | 用户提供原件或陈述，但未完成官方逐项核验 | 私有结构学习、方法审计、候选启发 |
| inferred / proposed | 从材料推断或为未来项目提出的方案 | 必须明确标注，不得伪装成已发生事实 |
| simulated | 演示或测试数据 | 只能用于产品演示/测试，不能进入真实研究结论 |

29 条 `official_verified` 卡片有意不补写公告无法证明的 `methods`、`summary` 或 `highlights`。接手者不得为了让卡片“更丰富”而取消这一约束。

## 时效与适用性

- 现有规则语料主要针对第十六届本科实践赛快照。
- 规则必须绑定届次、组别、赛区、赛道和阶段；不同版本不得混用。
- 新一届通知发布后，应先更新 `corpus-source` 并留下原文/快照和提取依据，再改变硬规则。
- 所有“获奖概率”“必胜”“保奖”式表述均不受支持；系统只提供准备度、证据和风险诊断。

## 品牌与匿名边界

“证见 EVI-X”是独立非官方 Agent 身份，不代表正大杯主办方。品牌可以用于 `agent_ui` 和 `public_promo`；竞赛提交物的 `competition_submission` 模式默认中性，匿名要求下不得出现 EVI-X logo、IP 角色或可识别团队信息。

## 部署边界

- `.openai/hosting.json` 只保存现有 Sites 项目标识、D1 逻辑绑定和空 R2 声明，不含密钥。
- 当前连接器访问该 Sites 项目时返回 `project_not_found`。接手者只能在用户明确授权后新建或替换 Sites 项目；不得自行改写项目标识。
- 压缩包不能证明线上站点当前可用，也不能代替生产 D1、身份头、登录隔离和迁移验证；截至 2026-08-26，生产站点与生产 D1 均未在线复验。
- 本地测试中的演示内存存储不等同于生产 D1。

## 安全验证边界

- `npm run verify` 中的依赖审计于 2026-08-26 报告 0 个已发现漏洞，但其结论只覆盖 `npm audit --audit-level=moderate` 的依赖范围。
- 静态审计后已修复空项目伪造、诊断无限落库、弱格式匿名密钥、无限项目创建、超限请求完整缓冲、项目/事件无上限返回、失败清空成功状态与无超时重试等问题。
- 尚未完成平台级全局限流、严格 CSP、请求 ID/脱敏运维日志，以及真实 Sites 入口对登录身份头清洗与注入的动态验证。
- 正式安全扫描工具在中文工作区路径上发生 GBK 解码失败，随后未产生可用 scan ID；当前状态是“工具阻塞”，不是“扫描通过”，也不是已确认的代码漏洞。
- 交接包不含任何正式扫描报告。接手者若重新扫描，应保留工具版本、扫描 ID、扫描范围、完整错误或结果以及复核结论。
